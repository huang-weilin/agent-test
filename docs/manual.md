# 使用手册

这套工具是给 **AI Agent 出考题的**：你告诉它测哪个 Agent、让它做什么、怎么算通过，它在一个隔离的沙盒里跑给你看，最后给你一页结论。不用写测试代码，不要求懂 Python 或 YAML。

---

## 1. 这东西是干什么的

一句话：**把"Agent 会闯什么祸"提前变成一份能重跑、能留档的测试**。

- 它搭了一套假的目标系统（假订单、假支付、假客服工单），Agent 在里面随便跑，不会动到真东西。
- Agent 的每一次工具调用都会被拦下来记一笔账：调了哪个工具、传了什么参数、结果如何。
- 跑完之后，拿"检测器发现的事"和你"事先声明预期的结果"对一对，出结论：通过 / 有问题 / 这次没测到。

它最擅长抓的几种毛病：

- **同一笔钱付了两次**（重复调用没有幂等保护）；
- **卡在循环里出不来**（一直重试同一个调用）；
- **没人看着时自己动手**（无人值守会话里干了没授权的事）；
- **记忆被写坏**（长期记忆污染、跨会话"忘记"之前确认过的事）；
- **参数写错**（调工具时传的参数不合规）。

它**不**做的是：给你写业务代码、替你做 Agent 的选型、或者保证"测过就没问题"——它只如实告诉你测了什么、结果如何。

## 2. 导航栏十个入口

左边那一栏就是全部入口。这一页（使用手册）也是其中之一。

| 入口 | 链接 | 什么时候点它 |
|---|---|---|
| **场景** | `/` | 看仓库里有哪些测试，挑一个跑 |
| **运行记录** | `/runs` | 看跑过哪些，点进某一次看完整报告 |
| **指标** | `/metrics` | 看最近一批测试的达成率和延迟 |
| **回归集** | `/regression` | 改完代码后，确认行为没变坏 |
| **体检** | `/checkup` | 不知道测什么？按行业或毛病一键开测 |
| **成本** | `/cost` | 看花了多少 token、多少钱 |
| **记忆** | `/memory` | 看长时运行的记忆快照和视野缺口 |

## 3. 快速上手：三分钟跑第一次体检

仓库里自带一个演示 Agent（`react_demo`）和一批现成的体检包，不用接任何你自己的东西就能先看一遍效果。

1. 左侧点 **体检**。
2. 选一个包——比如**电商履约体检**（同一单发两次、同一笔钱付两次这类毛病），或者通用体检里的**同一笔钱付两次**。
3. 点 **开始体检**。它会依次跑完包里的几支场景，一两分钟后出报告。

第一次跑完你会看到一页这样的结论：哪些毛病被抓到了（红）、哪些值得看一眼（黄）、哪些这次没事（绿）、哪些这次没测到（灰）。

**先跑这一遍**，比读任何说明都管用。跑通之后再看下面几章。

## 4. 读懂一份体检报告

体检报告的结构是固定的，从上到下：

1. **总览**：几项通过、几项抓到、几项没测到。
2. **抓到的**：Agent 把毛病犯了，而且被抓住了。每一行说明"在查什么、凭什么判的"。
3. **值得看一眼**：不算错，但有个值得留意的地方。
4. **这次没事的**：这几支剧本里没演出来问题。注意范围：只代表"这几支剧本里没发生"。
5. **这次判不了的**：没有足够信息能判，**不等于**没问题。列在这里正是为了不让你把它当成好消息。

每一条都能点进对应的运行记录看过程。**判不了 ≠ 全绿**，这是这套工具最想强调的一件事。

## 5. 跑一个场景：完整流程

场景（Scenario）就是一份测试定义。完整流程：

1. 左侧点 **场景**，看列表。
2. 找一份场景，点右侧的 **运行**。
3. 等待运行结束（几秒到几十秒，视场景长短）。
4. 跳转到**运行报告页**，看结论。

几个常见现象：

- 顶部出现"正在跑 xxx"：有运行在进行，此时其他运行会排队，等它跑完。
- 运行中被**熔断**：场景卡进循环时，看门狗会强制终止并记录，这正是场景想制造的结果，报告上会标清楚。
- 报告里"前提不成立"：某段会话没跑完就结束了，这时的结论不指向被测 Agent。

## 6. 自己建场景：三种方式

**最省事：说一句大白话。** 在首页点「用大白话建测试」（或直接打开 `/scenarios/plain`），把你想验证的事说成一句话，比如「同一笔钱会被付两次，应该能抓到」。机器把它翻译成一份测试，先给你看「打算怎么判」，你点头才存。没连上模型时，它用内置规则猜一份草稿——页面上会明说，存之前逐条检查就行。

**大多数人用向导就够了。** 左侧点 **场景** 页里的「跟着问题走」（或直接打开 `/scenarios/new`）。它只问三件事：

1. 测**哪个 Agent**（版本号，如 `react_demo@0.1`）；
2. 这一趟**让它做什么**（任务描述、几段会话、有没有人看着）；
3. **怎么算通过**（勾选你要检测的毛病：重复调用、循环、越权……）。

填完它会先给你看一遍「机器打算这样判」，你确认后才存盘。**没勾的方面，那一趟不算测过**——报告里会如实写"未覆盖"。

**进阶用户**可以直接用 YAML 编辑器改场景文件。完整字段说明见仓库 `docs/scenarios.md`。改完点保存，会先校验、通过才写盘。

## 7. 运行报告页怎么读

单次运行的报告是最要紧的一页，从上到下：

- **结论徽章**：通过 / 有问题 / 判不了，一眼看到头。
- **前提**：这段运行是不是按场景描述完整跑完了（每段脚本都被消费、没有提前被杀）。
- **各数据节**：世界时间（长时运行里过了多久）、自主行为（哪些调用是没人看着时发生的）、会话与记忆视野、调用链、跨会话差异、检测结论、工具审计、成本。
- **结尾两个操作**：
  - **存为回归用例**：把这次结论钉成基线，以后改完东西重跑对比（见第 12 章）。
  - **豁免误报**：你认为这条结论判错了，可以静音。注意：豁免改的是**以后的运行**，这一页报告一个字都不会变；而且它会进配置指纹，以后拿这次运行当基线时，比对结果会变成"改的是测试本身"，不再计数。

**调用链那一节是陈述，不是判定**：它只记录发生了哪些调用、顺序如何，不负责判断"谁的错"。判断在"检测结论"里。

## 8. 常见问题速查

| 问题 | 怎么办 |
|---|---|
| 界面打不开 | 双击 `start.bat`（或 `start.command`）启动，看黑窗口里的地址；详见本章末尾"打不开界面" |
| 点了运行，提示"正在跑另一个" | 同时只能跑一个，等它结束或去运行记录里看进度 |
| 一直停在"运行中" | 可能是 Agent 卡住了，超过单会话超时会被熔断；也可以去运行记录里看状态 |
| 报告里一大堆"判不了" | 说明那几项这次没有足够信息，常见原因是场景里没有对应的剧情（如没有无人值守会话） |
| 报告说"前提不成立" | 有会话没跑完，结论不指向被测对象；看是哪些会话、为什么中断 |
| 场景存不进去 | 保存前会先校验；页面上会显示错误原因，按提示改 |
| 不想花钱，只想先走通流程 | 用仓库自带的演示 Agent（`react_demo`）跑体检包，零成本 |
| 想把记录清空重来 | 见仓库 `docs/manual.md` 附录（删库重建的步骤） |

## 9. 接你自己的 Agent

三步：

1. 把你的 Agent 放进仓库的 `agents/me/` 目录（一个 `agent.yaml`：名字、版本、启动命令）。写法参考 `agents/react_demo/` 目录，接入方式见 `docs/scenarios.md` 与 `docs/decisions/001-integration-surface.md`。
2. 在向导里"测哪个 Agent"填 `me@0.1`（名字@版本），或者写场景时在 `agent:` 里引用它。
3. 先跑**只读**场景（不碰写操作），确认它能正常启动、能对话，再逐步放开写操作场景。

两个提示：

- 先空跑、再真跑：第一步先确认"接得上"，别一上来就测最狠的场景。
- 沙盒出口默认拒绝：你的 Agent 调用的任何外部服务，默认都会被拦下来记账。白名单在出口代理配置里，见 `docs/decisions/`。

## 10. 记忆与跨会话（长时运行）

如果你的 Agent 会被多次叫醒（云端常驻、跨会话），看 **记忆** 这一页：

- **快照**：每次会话前后，Agent 记忆的状态会被记下来（只记路径和摘要，不带内容）。
- **视野缺口**：某个会话是从旧快照恢复的，它开始时的记忆覆盖不到之前一段——落在缺口里的历史调用，Agent **不可能知道**。这时"重复操作"的责任在恢复机制，不在 Agent。
- **重复扣款这类跨会话事故**：Agent 周一让你订票、周三又订一次，靠的就是"记忆视野"来判断它本可以知道。

记忆页面回答的是"我们的操纵让它的视野从哪里开始"，不是"它记住了什么"。

## 11. 成本与预算

**成本**页回答两个问题：

1. **花了多少**：按天、按运行、按工具拆的 token 和金额。
2. **烧在哪儿**：哪个工具在吃上下文（"租金"是估算值，是下界不是账单）。

要点：

- 超预算**不会**让任何运行判为不通过——它只是对花费的陈述，和 Agent 这次做没做对无关。
- 预算阈值**默认关闭**：没配过的阈值一旦生效，会弹出没人认识的告警，告警一多就被整体忽略。要开，去成本页配一个。
- 金额以网关为准，不看 Agent 自己上报的用量（那是它能改的值）。

## 12. 回归集：改完代码怎么确认没变坏

流程：

1. 在某次运行的报告页点 **存为回归用例**——把这次结论钉成基线。
2. 改你的 Prompt 或工具。
3. 重跑同一份场景。
4. 去 **回归集** 页看差异报告：结论变了没有、变的是不是配置。

要点：

- **基线是冻结的**，不是"指向某次运行"。即使那次运行记录后来被清理，基线仍然在比。
- 改配置（比如豁免了一条告警）也会被检测出来——那时比对结果会说"改的是测试本身，不再计数"。

## 13. 指标页

**指标**页回答"最近这批运行怎么样"：

- **达成率**：结果和场景预期一致的比例。注意：它不叫"Agent 合格率"——它只说"预期达成没有"。
- **延迟**：报的是**中位数**（一次超时强杀能把平均值拉到离谱），附最大值看长尾。
- **失败原因**：分场景、分成因列不通过的运行。

范围默认看最近 50 次运行，页面上可以切 20 / 50 / 200。

## 14. 概念小词典与详细文档

先记这几个词：

- **场景**：一份测试定义（测谁、让它做什么、怎么算通过），就是一个 YAML 文件。
- **运行**：一份场景跑一次的过程，产生一份报告。
- **检测器**：专门盯一类毛病的检查器（重复调用、循环、越权……）。
- **结论**：检测器对某一条的判定（通过/有问题/判不了），配一句大白话解释。
- **豁免**：把某条结论静音的操作，有代价，见第 7 章。
- **基线**：被钉住供回归对比的某次运行结论。
- **视野缺口**：会话开始时记忆覆盖不到的历史段，见第 10 章。

详细文档都在仓库 `docs/` 目录下：

- `docs/scenarios.md`：场景文件完整字段。
- `docs/decisions/001-integration-surface.md`：Agent 怎么通过两个网络边界接入沙盒。
- `docs/detectors.md`：每个检测器的原理与阈值。
- `docs/cost.md`：成本口径与定价表。
- `docs/metrics.md`：指标口径。
- `docs/ui.md`：界面上每个标签/数字的含义。
- `docs/decisions/`：架构决策记录（ADR），最硬核的部分。
