# 使用手册

这套工具用来测试 AI Agent：你告诉它测哪个 Agent、让它做什么、怎么算通过，它在一个隔离的环境里把测试跑完，给你一份结论报告。不用写测试代码，不要求懂 Python 或 YAML。

---

## 1. 这东西是干什么的

它搭了一套假的目标系统（假订单、假支付、假客服工单）。被测 Agent 在里面随便跑，碰不到真东西。

- 每一次工具调用都会被记一笔：调了哪个工具、传了什么参数、返回了什么。
- 跑完之后，拿检测到的事和你事先声明的预期对一对，出结论：通过 / 有问题 / 没测到。
- 专门抓这几类毛病：重复操作（同一笔钱付两次）、死循环、无人值守时的越权行为、记忆被写坏、参数写错。

它不替你写业务代码，也不保证"测过就没问题"——它如实告诉你测了什么、结果如何。

## 2. 导航栏八个入口

左边那一栏就是全部入口。这一页（使用手册）也是其中之一。

| 入口 | 链接 | 什么时候点它 |
|---|---|---|
| **我的 Agent** | `/agents` | 登记你自己写的 Agent，登记完它就能被测 |
| **测试任务** | `/` | 看有哪些测试任务，挑一个运行 |
| **运行记录** | `/runs` | 看跑过哪些，点某一次看完整报告 |
| **报告** | `/metrics` | 看最近一批运行的结论汇总和报告列表 |

## 3. 快速上手

完整流程五步：

1. **连接你的模型**。打开「连接设置」，选一个服务商，填你的密钥，保存。不连也能用——机器会用内置规则先猜一版草稿，但连上后翻译更准。
2. **导入你的 Agent**。打开「我的 Agent」，把你自己的 Agent 目录登记进来（怎么接入见第 4 节）。想先看效果，也可以跳过这一步，直接用仓库自带的演示 Agent（`react_demo`）。
3. **建测试任务**。打开「测试任务」页，用「用一句话建测试」说一句你想验证的事（比如「同一笔钱会不会被付两次」），机器帮你变成测试；也可以走「一步步的向导」按问题选。
4. **运行**。在「测试任务」列表里点「运行」。一次只能跑一个，跑完自动出报告。
5. **看报告**。在「运行记录」或「报告」页找到这次运行，点进去看结论和问题。

## 4. 接入你自己的 Agent

### 4.1 在界面里登记

打开「我的 Agent」，填五个字段：

- **名字**：小写字母、数字、连字符、下划线，例如 `my_agent`。这个名字就是以后场景里引用的 Agent 名。
- **一句话描述**：显示在测试任务和自然语言录入里，方便认。
- **Agent 目录**：你机器上 Agent 所在的绝对路径。
- **入口文件**：相对于 Agent 目录的启动文件，默认 `agent.py`。
- **Python 命令**：留空就自动找目录下的 `.venv`，找不到就用系统 python。

登记完，这个 Agent 会出现在「用一句话建测试」的 Agent 选择里，也可以写进测试任务。

### 4.2 你的 Agent 需要怎么接入

被测时，引擎会在你的进程里注入这几个环境变量，入口脚本照它们办事：

| 环境变量 | 用途 |
|---|---|
| `SANDBOX_AGENT_TASK` | 这一段会话里用户说的话（你的任务） |
| `SANDBOX_GATEWAY_BASE_URL` | 模型网关地址（OpenAI 兼容格式），配 `SANDBOX_AGENT_API_KEY` 一起用 |
| `SANDBOX_AGENT_MODEL` | 模型名 |
| `SANDBOX_TOOL_BASE_URL` | 工具网关地址（调用被测工具用） |
| `SANDBOX_AGENT_MEMORY_DIR` | 记忆目录 |

可以参考仓库 `agents/react_demo/` 目录里的示例写法：用 OpenAI 兼容客户端连 `SANDBOX_GATEWAY_BASE_URL` 调模型，读完 `SANDBOX_AGENT_TASK` 就开工。

### 4.3 两个提醒

- 先只读、后写操作：第一步先确认"接得上"，再逐步放开写操作的场景。
- 沙盒出口默认拒绝：Agent 调用的任何外部服务默认都会被拦下来记账，这正是测试要看的。

## 5. 建测试任务

一个测试任务可以是**单个 Agent**，也可以是**一队 Agent 接力**（A 跑第一段、B 跑第二段）。

三种建法：

1. **用一句话建测试**（推荐给第一次用的人）。首页点「用一句话建测试」，或直接打开 `/scenarios/plain`：选要测的 Agent（可以多选，多选就是接力），然后说一句你想验证的事。机器把它翻译成一份测试，先给你看「打算怎么判」，你确认后才保存。
2. **一步步的向导**。测试任务页里的「跟着问题走」（或直接打开 `/scenarios/new`）：选 Agent → 说让它做什么 → 勾验证标准。
3. **直接编辑 YAML**（进阶用户）。场景文件在 `scenarios/` 目录下，字段说明见仓库 `docs/scenarios.md`。改完保存时会先校验，通过才写盘。

## 6. 设置验证标准

验证标准就是"怎么算通过"。建测试任务时，勾选你要检测的毛病：

- **重复调用**：同一工具被重复执行（比如同一笔钱付两次）。
- **循环**：一直重试同一个调用，出不来。
- **越权**：没人看着时干了没授权的事。
- **记忆污染**：长期记忆被写坏、跨会话忘记之前确认过的事。
- **参数不合规**：调工具时参数不符合声明。

没勾的方面，那一趟不算测过——报告里会如实写"未覆盖"。

## 7. 看报告

单次运行的报告页从上到下：

- **结论徽章**：通过 / 有问题 / 没测到，一眼看到头。
- **前提**：这次运行是不是按场景完整跑完了。
- **各数据节**：自主行为、会话与记忆、调用链、检测结论、工具审计、成本。
- **两个操作**：
  - **存为回归用例**：把这次结论钉成基线，以后改完东西重跑对比（见「回归集」页）。
  - **豁免误报**：你认为这条结论判错了，可以静音。注意：豁免改的是以后的运行，这一页报告不变。

「报告」页是所有运行的汇总：达成率、问题数、花费，每一行点进去看完整报告。

## 8. 连接你的模型

打开「连接设置」：

1. 选一个服务商（DeepSeek、OpenAI、Moonshot Kimi、智谱 GLM、通义千问，或自定义接口），接口地址和模型名会自动填好，也可以自己改。
2. 填你的密钥。
3. 点「保存连接」。

密钥只存在这台机器上（`.agent_sandbox_local.json`，已被 git 忽略），不会上传，也不会发给被测的 Agent。被测 Agent 在沙盒里拿到的永远是假凭据。

## 9. 常见问题

| 问题 | 怎么办 |
|---|---|
| 界面打不开 | 双击 `start.bat`（或 `start.command`）启动，看黑窗口里的地址 |
| 点了运行，提示"正在跑另一个" | 同时只能跑一个，等它结束或去「运行记录」看进度 |
| 一直停在"运行中" | Agent 可能卡住了，超过单会话超时会被强制终止 |
| 报告里很多"没测到" | 说明那几项这次没有足够信息，常见原因是场景里没有对应的剧情 |
| 报告说"前提不成立" | 有会话没跑完，这时的结论不指向被测 Agent |
| 场景存不进去 | 保存前会先校验，页面上会显示错误原因，按提示改 |
| 不想花钱，只想先走通流程 | 用仓库自带的演示 Agent（`react_demo`）建测试任务跑，零成本 |
