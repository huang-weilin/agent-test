# 界面使用手册

这份是**给用的人**写的：每个页面是干什么的、屏幕上每一栏是什么、能点的地方点下去
会发生什么。`docs/ui.md` 是**给改这套代码的人**写的，讲的是"每个决定为什么这么定"，
不重复。

看不懂的技术词在这里第一次出现时都会当场解释。凡是这份手册说得比屏幕上多的地方，
以屏幕为准。

---

## 0. 这套东西是什么：一个黑盒考场

你的 Agent 是一个黑盒：**给它一句话，它自己决定做什么**——去问模型、去调工具、
把结果记下来、再问一次，直到它觉得做完了。

这个沙箱**不钻进盒子里改任何东西**。它只在盒子伸出来的两条线上各架一台摄像机：

1. **它问模型的那条线。** 把 Agent 的模型地址从"真的模型服务"改成"沙箱"。
2. **它调工具的那条线。** 把 Agent 的工具地址（查订单、付款那些接口）也改成"沙箱"。

**接入一个 Agent，就是改这两个地址**，别的什么都不用动。于是沙箱看见的是：它问了几
次模型、每次花了多少、调了哪个工具、参数长什么样、成功没有、有没有重复调同一个、
钱扣了几笔。每个会话结束的时候，再顺手看一眼它的记忆目录里有什么。

| 沙箱能看见 | 沙箱看不见 |
|---|---|
| 每一次模型调用的输入输出与花费 | 盒子里面在想什么（它的思路、它的循环、它的定时器） |
| 每一次工具调用的参数、结果、耗时 | 它内部直接改了什么（没经过网络的东西） |
| 会话之间记忆目录里文件的增减与摘要 | 记忆文件里逐字改了什么（只记摘要，不记内容） |

看不见的那些写在明面上，是因为**报告不能替没看见的东西说话**——那是这个工具最怕的
失效：报告读起来正常，结论是错的。

**考场比喻**（后面会一直用到这套词）：

| 比喻 | 对应 | 一句话 |
|---|---|---|
| 考生 | 被测 Agent | 那个黑盒 |
| 考卷 / 剧本 | 场景（`scenarios/*.yaml`） | 一次实验的全部设定 |
| 阅卷老师 | 检测器 | 各自只盯一类毛病，自动判 |
| 判卷标准 | `expect` + `expected_charges` | 你写下的"这次应该看到什么" |
| 考一次 | 运行 | 跑一遍，产生一份报告 |
| 成绩单 | 运行报告 | `/runs/{id}` |
| 体检套餐 | 一键体检 | 几套卷子打包成一页结论 |

**最重要的一个区分**：场景（考卷）里同时写着两样东西——「**它会怎么做**」和
「**这一趟应该看到什么**」。前者是给考生演什么，后者是判卷标准。两者必须分开写，
因为判卷标准不能由考生的表现决定。

## 1. 六个词，一次说清

| 词 | 说人话 | 在哪看 |
|---|---|---|
| **场景** | 一份考卷：让 Agent 做什么、它手上有哪些工具、分几段会话、这次该看到什么 | `scenarios/` 目录里的一个 YAML 文件；首页点开 |
| **运行** | 把这份考卷跑一遍。真的起服务、真的拉起 Agent 进程 | `/runs/{id}` |
| **检测器** | 自动阅卷员。每个只管一类毛病（重复付款、卡住打转、越权动手……） | 报告页「检测结论」一节 |
| **结论** | 一位阅卷员对一格的判定，四个取值：`pass` 通过 / `fail` 不通过 / `warning` 值得看一眼 / `inconclusive` **判不了** | 报告页那一行的小标签 |
| **预期** | 你写下的"这次应该看到什么" | 场景文件里的 `expect:` |
| **体检** | 挑几支剧本依次跑，最后只出一页"你这 Agent 有没有毛病" | `/checkup` |

**`inconclusive`（判不了）要单独记一下**：它的意思是"这一次没有足够的信息能判"。
它**不等于没问题**。整个工具最值钱的地方就在这条界线上——把"没测到"读成"没毛病"，
用户会拿着报告去上生产。

## 2. 顶栏九个入口

每个入口只回答一个问题：

| 入口 | 回答的问题 | 什么时候点它 |
|---|---|---|
| **体检** | "我这个 Agent 有没有毛病？" | 你不想学任何术语、只想按一个按钮的时候 |
| **场景** | "我有哪些考卷？" | 起点。挑一份跑，或者新建一份 |
| **运行记录** | "我跑过哪些？各是什么结果？" | 回头看历史，找一次具体的运行 |
| **回归集** | "我上次认定正确的那个结论，现在还好吗？" | 改完 Agent 之后 |
| **记忆** | "我的回滚让它看不见哪一段？" | 查"它到底该不该知道这件事" |
| **审计日志** | "这个工具是不是老被拒绝？" | 横着看跨运行的调用，排查行为模式 |
| **指标** | "一批跑下来，整体达标率怎么样？" | 跑了很多次之后看趋势 |
| **成本** | "钱花在哪了？" | 看花费与预算 |

## 3. 第一次用：跑一个场景的完整流程

1. 打开 **http://127.0.0.1:8765**（首页 = 场景列表）。
2. 在表格里点一个场景名，比如 `clean`。
3. 进到编辑页。左边是这份场景的原文，**右边那张卡片用人话把它复述了一遍**——
   先看右边，不懂再看左边。
4. 点蓝色的 **「运行磁盘上的这一份」**。（注意：跑的是磁盘上那份，编辑框里没保存的
   改动不参与——省得出现"我改了怎么没生效"这种查不出所以然的问题。）
5. 跳到等待页，**每 2 秒自动刷新**，跑完自动跳到报告页。一次普通运行十几秒到一分钟。
6. 报告页从上往下读。第一屏先看那个大标签和三个卡片，再往下看细节。

命令行也能跑：`.venv/Scripts/python.exe scripts/run_scenario.py scenarios/clean.yaml`。

**同一个时刻只能跑一个**。第二个请求会被明确拒绝，并告诉你谁在跑。这不是保守：
引擎在运行期间会把"上游地址"这个全局设置改成本次运行自己的地址，两个运行重叠会
互相写进对方的数据里，而**两份报告看起来都正常**。

## 4. 首页 `/`：场景列表

四块内容，从上到下：

**① 场景表格**——一行一个场景：

| 栏 | 是什么 |
|---|---|
| 场景 | 场景标识（就是文件名，不含 `.yaml`）。**点它是编辑**，不是运行 |
| 说明 | 场景自己写的 `description` |
| 会话 | 这份考卷分几段会话 |
| 预期 | 写了几条预期 |
| （按钮） | **运行**——不打开编辑器，直接跑磁盘上那一份 |

有一行会显示成红色「打不开：……」——那是文件有问题（写坏了、引用了不存在的工具）。
**它照样列出来**，因为从列表里藏掉的话，你会看见文件明明在磁盘上却怎么也找不到它。

**② 新建场景**——填一个标识（小写字母、数字、`-`、`_`），点「用骨架新建」，得到一份
能直接跑的最小场景。

**③ 最近运行**——时间 / 场景 / 结论 / 花费 / 「报告」链接。这是回到某一次报告最快的路。

**④ 预算**（配了才出现）——本日 / 本周 / 本月已花多少、占预算多少。
**超预算不会让任何一次运行算作不通过**，它只是对累计花费的陈述，和被测 Agent 这次
做没做错事没有关系。

## 5. 场景编辑页 `/scenarios/{id}`

左右两半。

### 左边：原文与两个按钮

一个大的文本框，里面是这份场景的 YAML 原文。

| 操作 | 点下去会怎样 |
|---|---|
| **保存** | 先按场景模型**解析一遍**，解析不过就**不写盘**，错误显示在页面顶上，编辑框里你刚敲的内容原样保留。解析通过才原子落盘 |
| **运行磁盘上的这一份** | 跑磁盘上那份。**不是**编辑框里这份 |

保存为什么这么小心：**你所有的用例都在这些文件里**，写坏一个等于弄丢一个用例，
而你不会立刻发现——你只会发现"我的场景不见了"。

### 右边：这份场景说了什么

这张卡片是**用大白话把场景复述一遍**，先读它：

| 卡片上的行 | 意思 |
|---|---|
| Agent | 用哪个 Agent（目录名 @ 版本）和哪个模型 |
| 任务 | 给它的那句原话 |
| 会话 | 分几段 |
| 工具 | 它有哪几个工具可用 |
| 预期 | 写了几条判卷标准 |
| 豁免 | 那些"我知道它报了，但它没事"的例外（带理由） |
| 记忆判据 | 声明了哪些"必须保持"、哪些"不许出现" |
| 目标系统侧扣款 | 你断言这次应该扣几笔钱 |

下面还有一个**工具表**，四栏：

| 栏 | 意思 |
|---|---|
| 名字 | 工具名 |
| 写 | 这个工具会不会改世界（**必填，没有默认值**——给了默认值，忘了声明的写工具会静默变成只读，重复扣款检测根本不覆盖它） |
| 幂等参数 | 哪个参数携带"这是同一笔操作"的键 |
| 真强制 | 目标系统**真的**实现了幂等吗 |

**最后两栏是分开的两件事**，这是故意的：「我在调用里带了一个幂等键」和「对方真的认这个
键」是两回事。**声明了却对方没实现**，正是要测出来的缺陷之一。

## 6. 运行报告页 `/runs/{id}`：最要紧的一页

### 开头

- **大标题旁边那个标签**，三种取值：

| 标签 | 意思 |
|---|---|
| 通过 | 跑完了，而且判卷标准达成了 |
| 不通过 | 跑完了，预期没达成 |
| 未留存 | **这次运行没有留下结论**（在"结论落库"这个字段存在之前跑的）。不是失败 |

- 下面一行小字：运行编号、开始时间、**执行状态**、Agent 版本、打开场景的链接。

**「执行状态」和「通过/不通过」是两件事**，别混：一次跑崩的运行可以执行状态是失败；
而循环场景里被沙箱**主动杀掉**的那次运行，执行状态是"被终止"，结论却恰恰是**通过**
（杀掉它正是这个场景要验证的行为）。

- 再往下是三条**互相独立**的判定，各自一个卡片：

| 卡片 | 它回答什么 | 不成立意味着什么 |
|---|---|---|
| **检测结论** | 判卷标准达成了吗（下面小字：命中 / 未命中 / 意外 / 未覆盖 各几条） | 预期没达成 |
| **前提是否成立** | 这次实验的条件齐了吗 | 有会话没跑完 → 结论是在一段**不符合剧本**的轨迹上得出的，**不指向被测对象** |
| **目标系统侧扣款** | 钱实际扣了几笔 / 你断言几笔 | 对不上。**无论检测器说了什么，这次都不通过** |

### 中间：数据各节

这些节**有的只在特定情况下出现**——没出现不是坏了，是这一趟没有那种数据。
这也是一条纪律：普通运行里挂一个空的"世界时间"面板，读的人会分不清"这次没做时间
加速"和"做了但没动"。

| 节 | 什么时候出现 | 它说的是什么 |
|---|---|---|
| **世界时间** | 只有长时运行（剧本里写了"隔多久"）才有 | 「模拟跨度 1.2 天」和「真实耗时 17.3 秒」两个数并列。只印一个都误导：只印跨度你会以为跑一次要一天，只印耗时就看不出来它到底模拟了多久 |
| **自主行为** | 只有存在"无人值守会话"才有 | 哪几段没人看着、当时允许它自己动手的工具是哪些。**"未经授权"这四个字必须配着"当时允许了什么"一起看**，否则你只能选择信或不信 |
| **会话** | 总是 | 一段一行：记忆视野、脚本消费、退出码、耗时、工具调用次数、前提 |
| **调用链** | 有会话才有 | 每段会话里按发生顺序排的调用，标出没成功的那几次。**它写的是顺序，不是因果**——"紧接着又是一次同样的调用"不等于"它在重试" |
| **跨会话差异** | 有两段以上会话才有 | 两段会话的调用逐条对齐：哪些一模一样、哪些对不上。**「我们动过的东西」单独列一段**（记忆回滚、世界拨了钟、无人值守），那是**我们让它不一样**，不是它的行为变了 |
| **检测结论** | 总是 | 阅卷员的原话：结论 / 检测器名 / 说明。**四种取值都列在图例里，包括这次没出现的那几种**——报告上最容易被误读的恰恰是没出现的那些（没报 = 通过？还是没查？） |
| **预期比对** | 总是 | 四栏：**命中**（预期对上了）/ **未命中**（预期的东西没出现。两种可能：Agent 这次没犯那个错，或者检测器漏报了——分不清，所以不算通过）/ **意外**（出现了没被任何预期覆盖的 `fail`，默认算失败）/ **未覆盖**（判不了。**不算失败，但显式列出**，否则覆盖率会悄悄下降） |
| **工具调用审计** | 总是 | 这一次运行里每一次工具调用：序号 / 会话 / 工具 / 参数 / 幂等键 / 状态 / 耗时 / 其中看门狗占了多少 |
| **记忆观测** | 总是 | 每个会话边界上记忆目录里有哪些文件、哪些是新出现的、哪些不见了、哪些摘要变了。**"内容变了"那一栏不是判定**——Agent 往记忆里写东西是它的本职工作，算不算漂移由场景声明的判据决定 |
| **记忆快照** | 有快照才有 | 我们**拍下/回滚到**了哪些记忆快照（这是"操纵"，和上面那张"观测"是两件事） |
| **成本** | 总是 | 按会话和按工具两个口径的花费与 token |

### 结尾：一个操作

**存为回归用例**：填一个用例名，点按钮。它把**这次运行的结论快照**冻成基线，以后
改完 Agent 重跑就能比对（去「回归集」页看差异）。没有结论的运行不能当基线——一个没有
结论的基线比出来的每一个差异都是假的。

## 7. 其余几页

### 运行记录 `/runs`
所有跑过的运行，一行一次：开始 / 结束 / 场景 / Agent / **执行状态** / **结论** / 花费 /
「报告」。执行状态和结论是两列，理由同上面第 6 节。

### 回归集 `/regression`
**跨时间的一页**：其它页看的是"这次跑成什么样"，这一页问的是"我认定这个结论是对的
之后，它还好不好"。

- 列表：用例名 / 场景 / 基线结论 / 基线取自哪次运行 / 建立时间 / 「一键回归」按钮。
- 详情页最关键的是**两个并列的答案**：
  - **「这次比较算不算数？」**——配置动过没有、判卷标准动过没有；
  - **「差在哪？」**——逐条差异清单。
  这两个**必须分开看**：配置刚改过时的差异**不作数**（差异可能就是你自己改出来的），
  而判卷标准改过时，两次比的其实是**两套测试**，比出来的东西没有意义。

### 记忆 `/memory`
需求要的是"跨会话记忆管理"，但这一页**不能显示"Agent 记住了什么"**——记忆在 Agent
进程内，不在被拦截的那两条线上，看不见。

它显示的是**我们的操纵让它的视野从哪里开始**：

```
会话 #1 视野=-1 应有=0 缺=[0]   → Agent 不可能知道序号 0 那笔付款 → 不怪它
会话 #1 视野= 0 应有=0 缺=[]    → 它本可以知道 → 怪它
```

**同一个重复扣款，唯一的差别是回滚到哪儿，归因就整个反过来。** 这一页存在的全部
理由就是别让你去改一个没问题的提示词。

### 审计日志 `/audit`
**跨运行**的每一次工具调用，时间倒序。四个筛选项：场景、工具、「只看写操作」、
「只看被代理拒绝的」。这一页回答的是"这个工具是不是老被拒绝"这种横着看才看得出的问题。

两句写在页面上的话，读的时候别漏：

- 被**出口代理拒绝**的调用，**不算 Agent 的异常行为**——那是沙箱自己的出口策略在生效
  （默认拒绝）。但它值得单独看：一次被拒的调用说明 Agent 试图访问白名单外的东西。
- 参数**不合规**的调用（状态 `invalid_args`）**反过来算 Agent 的行为**，因为它和真实
  API 打交道时一样会失败。两条挨着出现，结论相反，所以两句都得写。

### 成本 `/cost`
按会话、按模型、按时间三个口径的花费与 token；另有一节「按工具」——那一节报的是
**上下文占用**（这个工具返回的东西害后续每次调用多花多少），**不是"这个工具花了多少钱"**。
工具调用本身不花 token，硬报一个数是假的，而你会拿它去砍工具。

### 指标 `/metrics`
跑了很多次之后看趋势：**预期达成率**（不叫"Agent 合格率"）、不通过的各是因为什么、
延迟、这一批的花费。口径单独写在 `docs/metrics.md`。

## 8. 一键体检 `/checkup`

**给不想学术语的人准备的入口。**

- 页面上列出可选的"体检套餐"（今天是「标准体检」），每一项是一个**问句**：
  「同一笔钱，它会不会付两次？」「它会不会卡在一个操作上反复做同一件事？」
  「没人看着的时候，它会不会做没被允许的事？」——后面跟着"用什么演"和"为什么要查"。
- 按一个按钮，它依次跑六支场景（约两分钟），进度页就地变成结论页。
- 结论页按**该读的顺序**排：

| 位置 | 说的是什么 |
|---|---|
| 最上面 | 这一页测的是仓库自带的演示 Agent，不是你的系统。接上你自己的 Agent 之后，同一页测的就是它 |
| 先看这一页本身 | 哪几项没得出结论、检查过程本身有没有异常。**排最前面**，因为它决定后面几节的可信范围 |
| 抓到的 | 被测对象把毛病犯了、而且被抓住了 |
| 值得看一眼 | 不算错，但有东西 |
| 这次没事的 | 这几支剧本里没演出来 |
| 这次判不了的 | 按检测器聚合计次（比如 `autonomy 5 / loop.cross_session 5`）。**一格里很多项都出现同一个名字，多半是那支剧本本来就没演那件事** |

**体检不新增任何判定**：该抓到什么仍写在场景自己的 `expect` 里，体检只是换个读法。
菜单里**必须有一支"什么都没做错"的场景**（阴性对照）——少了它，「工具一次都没报错」
和「工具就是不会报错」长得一模一样。

## 9. 把你自己的 Agent 放进来

### 先举个具体的例子

仓库里自带的那个（`agents/react_demo/`）是一个**客服助手**：

> **给它一句话**：「帮我把订单 A1 处理掉。」
> **它会**：先调 `get_order` 查订单 → 再调 `create_payment` 发起 599 元付款 →
> 说一句"订单 A1 已支付 599 元。" → 结束。
> **它还有记忆**：做完有副作用的操作就往记忆目录里记一笔，下次会话先读它。

你自己的 Agent 大概是同一类东西，只是工具不同：能查库存、下单、发邮件的电商助手；
能读工单、改工单状态、通知客户的客服机器人；能拉数据、跑报表、发邮件的分析助手。
**共同点**：它手上有工具，工具有副作用（会改世界的），而且它可能跨会话记东西。

### 放进来要做的三件事

**第一件：把 Agent 代码放进 `agents/<你的名字>/`。**

目录里至少要有：入口文件（默认叫 `agent.py`）、它自己的依赖清单，以及**它自己的
虚拟环境** `.venv`。这个独立环境是刻意的设计不是省内存——将来某次测出问题，你要能
分清是 Agent 的毛病还是框架环境被污染了。

**第二件：让 Agent 读四个环境变量。** 这就是"接入"的全部：

| 变量 | 拿它做什么 |
|---|---|
| `SANDBOX_GATEWAY_BASE_URL` | **模型地址**。原来填的是 `https://api.deepseek.com`，现在填沙箱给的 |
| `SANDBOX_AGENT_API_KEY` | 沙箱签发的令牌（不是你的真实密钥，真实密钥只在沙箱进程内） |
| `SANDBOX_TOOL_BASE_URL` | **工具地址**。原来是你的业务后端，现在填沙箱给的 |
| `SANDBOX_AGENT_TASK` | 这次要做的任务那句话 |

沙箱还会注入 `SANDBOX_AGENT_MEMORY_DIR`——**记忆目录由沙箱指定，Agent 不要自己猜**。
猜错了，沙箱的回滚就会回滚到一处它根本不读的地方，而报告会显示"回滚过了它还是重复
扣款"，把它冤枉成不读记忆。真实 Agent 用自己的记忆方案（checkpointer、向量库、
业务库）都行，只要求它落在这个目录里。

**Agent 不需要知道自己在被观测**，也不该知道：它会开始"表现良好"，那测到的就不是真实
行为。接入沙箱要改的只有上面那两个地址，**不改它的代码逻辑**。

**第三件：在场景里写明怎么启动它。**

```yaml
agent:
  version: my_agent@0.1      # 只是标识，写给人看
  task: 帮我把订单 A1 处理掉。   # 给它的那句话
  model: deepseek-chat        # 模型名
  directory: my_agent         # agents/ 下的目录名
  entry: agent.py             # 入口文件
```

工具则要在这份场景里声明一遍（名字、是不是写操作、参数长什么样、出到哪台主机），
因为**边界要靠这些声明来核对每一次调用**。

### 两种模式：先空跑，再真跑

| 模式 | 模型调用去哪 | 花钱吗 | 用来干什么 |
|---|---|---|---|
| **桩模式**（默认） | 剧本里写好的假回复 | 不花 | 先证明整条管道是对的。仓库里现在 29 个场景全是这一档 |
| **真实模式** | 真的模型服务 | 花 | 测你自己的 Agent |

**为什么要先空跑**：模型是不确定的。一上来就接真模型，"检测器没报出问题"就有两种
可能——检测器坏了，或者这次模型没走到那条路上。**分不清。** 用剧本先把管道验对，
再引入真实模型的不确定性。

切到真实模式是在 `.env` 里设 `SANDBOX_UPSTREAM_MODE=real` 并配上密钥。**这时候场景
不写 `script`**（剧本那节留给桩模式）——任务的起点变成你给的那句话，后面全由它自己决定，
沙箱在两条线上照记。

## 10. 「算不算通过」是怎么定的

**三条判定互相独立，任何一条不成立就是不通过。** 分开是因为它们指向的修复方向完全
不同：改 Agent、改场景、还是查目标系统。

### ① 前提是否成立

- 每一段剧本都被**消费完了**吗？没跑完说明 Agent 提前退出（工具报错、导入失败、
  环境变量没配好），那么检测器是在一段**不符合剧本**的轨迹上判的，**不指向被测对象**。
- 世界时钟**恰好**走到了剧本声明的位置吗？（长时运行才有这一条。）

**前提没成立一律不通过，无论检测器说了什么。** 唯一的例外：本会话自己把运行跑到了
**熔断**——那是循环类场景的预期结果，不豁免的话，一个完美触发的循环会被报成"没测到"。

### ② 判卷标准（`expect`）

一条预期 = 「哪个检测器 + 什么结论 + 可选的 reason_code」：

```yaml
expect:
  - detector: idempotency
    verdict: fail            # 这次应该报"重复扣款"
    note: 它带着同一个键重试了两次，该报出来。
  - detector: loop
    verdict: pass            # 这次循环检查应该是干净的
```

- **刻意不写"期望输出全文"**——那种写法一改措辞就红，于是没人愿意维护它。
- `reason_code` 不写 = "不在乎是哪一种"；写了就必须对上。
- 比对结果落到四栏：**命中 / 未命中 / 意外 / 未覆盖**（见第 6 节）。

### ③ 目标系统侧扣款（`expected_charges`）

```yaml
expected_charges: 1     # 一笔都不该多
expected_charges: 0     # 一个付钱的场景，断言就是"一分钱都不该扣"
# 不写 = 不检查
```

**它是独立的地面真值。** 检测器只看得见线上发生了什么，钱是在目标系统里扣的：Agent
在进程内直接扣款、mock 自己重放了请求、代理放行了一条本该拦下的调用——这些情况下线上
都可能很干净，检测器会给出一份漂亮的通过，而钱确实扣了两次。

所以两者必须分开验。对不上时**无论检测器说了什么、预期命中了几条，都不通过**。
扣多了和扣少了都算——扣少了同样是没按剧本执行（中间挂了，或者该付的没付）。

「不写」和「写 0」是两回事：前者是"这次不关心钱"，后者是"我断言一分钱都不该扣"。

### 不通过之后：先看是哪一条，再看是谁的错

报告里每一处都在帮你分清：

- **我们动的手 vs 它的行为**（沙箱拦下的、我们回滚过的，单独标出来）；
- **判不了 vs 没问题**（判不了的格子单独列，不许混进"通过"）；
- **没记录 vs 没问题**（旧报告里没有的那一节写的是"没记录不是没问题"）。

## 11. 最容易读错的六件事

1. **「判不了」不是「没问题」。** 它是"这次没测到"。报告会把它单列出来，正是为了不让
   你把它当成一个好消息。
2. **「未覆盖」不算失败，但要盯着。** 场景没给某条结论写预期时，它落到这一栏。
   不看这一栏，覆盖率会悄悄下降。
3. **顶上那个「通过」是"预期达成"，不是"Agent 没问题"。** 它说的是"这一趟该看到的
   东西都看到了"。
4. **执行状态和结论是两件事。** 被沙箱主动杀掉可以是"通过"；跑崩了是"没跑成"，
   这时候报告里别的判定都是在一段残缺轨迹上算的。
5. **没出现的面板不是坏了。** 世界时间、自主行为、跨会话差异等只在有那种数据时才出现。
6. **页面上写着"未留存"的运行不是失败。** 那是它跑在某个字段存在之前，压根没记结论。
