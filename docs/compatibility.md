# 外部 Agent 导入兼容矩阵

**这份文档回答一个问题**：外面平台上做的 Agent，能不能导入本工具做行为测试？
答案不是"能"或"不能"，是**按来源分档**——不同平台导出的东西根本不是同一种
东西，导入后的检测能力也不一样。

## 一、先分清两种底层实现

主流平台的 Agent 产品可以分成两类，分界在**导出物是不是可执行代码**：

| 类型 | 代表 | 导出物 | 运行时 | 一句话 |
|---|---|---|---|---|
| 代码型框架 | LangGraph、LangChain、CrewAI、AutoGen | Python 代码 + 配置（如 `langgraph.json`） | 代码即程序（本地进程 / API 服务 / 云端部署） | 和我们仓库里的 Agent **同源**——都是 Python + OpenAI 兼容 LLM + 工具函数 |
| 平台低代码型 | 扣子 Coze、Dify、阿里云百炼 | DSL / Zip / JSONL（节点图、Prompt、工具参数的**配置**） | 平台后端运行时（Dify 开源可自托管；扣子是闭源云端） | 导出物是**画布定义**，不是程序；要靠平台的运行时解释执行 |

关键事实：Coze 把智能体导出为 Zip、Dify 导出 DSL（YAML/JSONL）、阿里云百炼能
一键导入 Dify DSL——**这些都是在"配置层"互导**，没有一个平台导出的东西能
直接当程序跑。而 LangGraph 生态（LangSmith Fleet）可以把 Agent 导出成代码包，
那是另一回事（见下）。

## 二、兼容矩阵

本工具的沙盒协议要求被测对象满足：**进程化入口（`main()`）+ 环境变量注入 +
工具调用走本地 mock（`SANDBOX_TOOL_BASE_URL`）+ 记忆目录注入**。按这个标准分三档。
**范围决定（2026-10-11）**：只考虑代码型框架这一档；自托管运行时与闭源云端都
不纳入——前者要把第三方运行时整体装进沙盒并持续跟进版本，成本高于价值；
后者形态上不可测。

| 来源 | 能否导入做行为测试 | 检测能力 | 接入路径 | 现状 |
|---|---|---|---|---|
| 代码型框架（LangGraph/LangChain/CrewAI/AutoGen） | **能**，需一层适配 | 全量（幂等/循环/记忆/成本/自主全部可用） | 写薄 wrapper：读我们的环境变量 → 调它的主逻辑 → 把工具调用重定向到本地 mock；用 `AGENT.json` 注册（entry / python 自定义） | 黑盒边界与框架无关（设计推论，尚无框架外实例实测） |
| 自托管开源运行时（Dify 等） | **不纳入**（成本高于价值） | 工具级检测可用，但要把第三方运行时整体装进沙盒、对齐工具协议、跟进版本，维护成本远高于收益 | — | 明确不做（2026-10-11 决定） |
| 闭源云端平台（扣子 Coze、豆包、百炼云端） | **不能做工具级测试** | 仅黑盒（通过公开 API 测行为），幂等/循环/记忆/成本基本失效 | 无——云端 Agent 调不到本机 mock | 未做（形态上不可测，见下） |

### 为什么闭源云端那档"不能"

我们的核心检测（幂等、循环、记忆、成本）全部依赖**拦截 Agent 的工具调用**和
**注入本地 mock**。云端 Agent 的执行发生在对方服务器上，物理上永远调不到本机
`127.0.0.1` 的 mock，所以：

- 幂等/循环：看不到它的调用序列，无从判起；
- 记忆：记忆在它云端的进程/存储里，我们注入不了 `SANDBOX_AGENT_MEMORY_DIR`；
- 成本：计费在它的账上，我们的网关量不到。

最多只能通过它的公开 API 做黑盒行为测试——需要真实 key、真实消耗，偏离本工具
"零成本、可控、可复现"的核心价值。

## 三、能力分档（对外承诺的口径）

产品对外说"支持导入外部 Agent"时，必须同时说清**哪一档**，不能说成统一能力：

1. **全量检测档**：代码型框架 Agent，经适配层接入。六类检测全部可用。
2. **黑盒档 / 不承诺**：自托管运行时与闭源云端 Agent 均不纳入。前者成本高于价值，
   后者形态上不可测——对外不承诺这两档。

## 四、配套的适配层需求（仅代码型框架）

接入代码型框架 Agent，需要本工具新增**适配器层**（当前 `AGENT.json` 注册表只是
起点，只解决了"不同目录/入口/解释器"，还没解决"不同工具调用协议"）：

- 把外部 Agent 的工具调用协议翻译成本工具 mock 的工具协议；
- 把本工具的环境变量约定映射成外部框架自己的初始化方式；
- 报告里标注"被测对象经适配器接入"，区分原生 Agent 与外部 Agent。

该适配层**尚未开发**（现状：无外部框架实例实测，见需求覆盖表「兼容性」行）。

## 五、查证来源

- 扣子：低代码工作流支持导出 Zip；智能体可部署为 API 服务 / Web SDK（docs.coze.cn）
- Dify：Workflow 支持 DSL 导出/导入，可自托管（dify.ai / 阿里云百炼支持一键导入 Dify DSL）
- LangGraph：代码 + `langgraph.json`，可本地 server / 云端部署；LangSmith Fleet 支持导出代码包（docs.langchain.com）
- 火山引擎 AgentKit：提供迁移工具与 VeADK Runtime（docs.volcengine.com）
