```bash
./.venv/Scripts/python.exe scripts/serve_ui.py            # → http://127.0.0.1:8765
./.venv/Scripts/python.exe scripts/serve_ui.py --port 8770
```

## 零 JavaScript

轮询用 `<meta http-equiv="refresh" content="2">`，保存用 form POST，删除以外没有
任何交互需要脚本。所以浏览器关掉 JS 它照样能用，也没有"前端资源没构建"这类故障模式。

代价说清楚：**运行中页面整页刷新**，输入框里没提交的编辑会丢。这在等待页上无所谓
（那里本来没有输入框），但意味着不能把编辑器和运行状态放在同一页。目前是分开的。

## 五条约束

### 1. 只绑回环地址，且不给远程开关

`serve()` 对 `127.0.0.1` / `::1` / `localhost` 之外的主机**直接抛 `ValueError`**，
不是打警告。这个服务没有任何认证，而它能写场景文件、能拉起子进程——绑 `0.0.0.0`
等于把"往这台机器上写文件"开放给整个局域网。

刻意**不留** `--host` 逃生舱：留了就等于认可那条路。要远程访问，用 SSH 端口转发；

```bash
ssh -L 8765:127.0.0.1:8765 <主机>
```

那条路上至少有认证和加密。`tests/test_api.py` 里有一条测试直接钉住
`DEFAULT_HOST == "127.0.0.1"`，另一条钉住 `serve()` 会拒绝 `0.0.0.0`。

### 2. 一次只跑一个，第二个请求返回 409

不是保守，是执行器**物理上不能并发**：它运行期间改进程级全局
`settings.tool_upstream_base_url`（`runner.py:342`），把出口代理指向本次运行自己那个
mock 的端口。两个运行重叠的话，后启动的会把前一个的地址改掉——前一个的代理于是去敲
**后一个的 mock**，两边数据互相写进对方的目标系统，而**两份报告都看起来正常**。

这正是本项目一直在防的那类失效：报告读起来没问题，结论是错的。

**不做队列。** 第二个请求直接拒绝，并明说"`clean` 正在跑，等它结束"。排队更友好，
但用户对着一个没有解释的转圈等一分钟，不如收到一句能读懂的话。

判断"有没有人在跑"没有加锁：asyncio 单线程，而检查与置位之间没有 `await`，
从事件循环视角是一步完成的原子操作（`api/jobs.py`）。

### 3. 结论标签有三种，`NULL` 不是 `False`

`TestRun.verdict_ok` 是**可空**的，界面上对应三种显示：

| `verdict_ok` | 显示 | 含义 |
|---|---|---|
| `True` | `通过` | 运行跑完，判定通过 |
| `False` | `不通过` | 运行跑完，判定不通过 |
| `NULL` | `未留存` | **没有留下结论**——加这个字段之前跑的历史运行 |

把 `NULL` 显示成红叉，等于替一条没有结论的运行编一个结论出来，用户会去查一个根本
不存在的缺陷。`report_json` 同理：`parse_report()` 对老运行返回 `None`，页面与
`/api/runs/{id}` 都明确说"未留存（在本字段存在之前跑的）。**不是失败。**"

`verdict_ok`（**判定**）与 `status`（**执行**）是两件事，不要合并：一次正常跑完的运行
完全可能不通过；而 `loop` 场景里被熔断杀掉的那次运行，`status='killed'` 却恰恰是**通过**的。

结论与运行分两次写：`finish_run()` 在执行结束那一刻发生，而结论要等检测器跑完、
预期比对完才知道（`trace/recorder.py` 的 `record_verdict`）。作业**先**记录结论、
**再**置 `state="done"`，所以跳到报告页时结论一定已经落库，不会闪出"未留存"。

### 4. 场景标识走白名单

`api/paths.py` 是**整个 Web 层唯一碰磁盘的地方**。从 URL 取来的字符串会被拼进文件
路径，不校验就是一个任意文件写。两道防线：

- 标识必须匹配 `^[a-z0-9][a-z0-9_-]{0,63}$`——挡掉分隔符与 `.`；
- 拼出来的路径再做一次**包含性检查**（`path.parent != base` 就拒绝），
  这一道不依赖正则的细节。

`tests/test_api.py` 用 13 个畸形标识参数化钉住这件事：`../`、`..\`、`a/b`、
`/etc/passwd`、`C:/windows`、空串、大写 `Clean`、`.hidden`、`clean.yaml`（扩展名会
变成 `clean.yaml.yaml`）、含空格的、65 字符的超长的、非 ASCII 的。另有一条走 HTTP
层，用 URL 编码的 `..%2F..%2Fetc%2Fpasswd` 确认路由层不越权。

列场景时**文件名不合法的也照样列出来**，并说明它为什么打不开。从列表里藏掉的话，
用户看见文件在磁盘上却怎么都找不到它。

### 5. 保存之前先校验

写进磁盘的文本必须先能被 `load_scenario` 读出来。**全部用例都在这些文件里，写坏
一个等于弄丢一个用例**——而用户不会立刻发现，他只会发现"我的场景不见了"。

校验不过时不落盘，并把**用户刚敲的内容**回显到编辑框（不是磁盘上的），否则一次
笔误就变成一次静默的改动丢失。落盘走 `tempfile.mkstemp` + `os.replace`，是原子的。

连"新建场景"的骨架也要经解析器过一遍——不然就会有一个"编辑器一保存就报错"的默认场景。

## 顺带定下的几件事

| 决定 | 为什么 |
|---|---|
| **没有 JSON 写接口** | 改场景文件只有 HTML 表单一条路，于是路径校验、先校验后落盘只在一个地方落地，不用维护两套写入口的等价性。将来真需要，把表单处理器抽出来即可 |
| **场景不存在就 404，不给空编辑器** | 空编辑器点保存就凭空建出一个场景来，于是"新建"有两条路径，其中一条用户根本不知道自己走了。新建只有一个入口：列表页那个表单 |
| **跑的是磁盘上那份，不是编辑框里的** | 未保存的改动不参与运行。不然"我改了怎么结果没变"会变成一个查不出所以然的问题。页面上也这么写 |
| **关掉 `/docs` 与 `/redoc`** | 它们没有任何认证，而这个服务能拉起进程。接口不复杂，`/api/*` 的路径本身就是文档 |
| **`reload=False`** | 热重载会在文件变动时重启进程；一次运行正在跑的时候重启，会留下一批"永远进行中"的运行记录 |
| **模板引擎（Jinja2）** | **引它的理由是自动转义，不是排版。** 检测器结论、Agent 的 stdout、工具参数全是外部输入，手写 f-string 拼 HTML 意味着每一处都要记得 `html.escape`，漏一处就是一个 XSS。有一条测试专门钉这件事 |

## 三个"视图"模块，难点都不在查询

需求第 229 行的六个模块里，`记忆视图`、`审计日志`、`回归集` 都是在已有数据上面
看东西，难点不在查询本身：前两个技术上很薄，真正要花心思的是**别把话说错**——
它们各自有一句话会说反；第三个有真的逻辑（差分引擎），但它的风险一样是**给出一个
读起来像结论、其实不作数的结论**。

### 记忆视图 `/memory`

需求 3.4 要的是"跨会话记忆管理"。但这一页**不能显示"Agent 记住了什么"**：
记忆在 Agent 进程内，不在 ADR 001 的网络边界上，边界拦不到它。

所以它显示的是**我们的操纵让它的视野从哪里开始**。判据是
`Session.memory_horizon_ordinal`，页面上把缺口显式算出来：

```
会话 #1 视野=-1 应有=0 缺=[0]   → Agent 不可能知道序号 0 那笔付款 → 不怪它
会话 #1 视野= 0 应有=0 缺=[]    → 它本可以知道 → 怪它
```

**这两行是整个三方受控实验的 UI 版。** 同一个重复扣款，场景、脚本、扣款
次数全都一样，唯一的差别是回滚到哪儿——于是"缺不缺序号 0"就是归因的全部依据。
说反了用户会去改一个没问题的 Prompt，这正是这一页存在的理由。
`test_attribution_flips_on_the_gap_alone` 钉的就是这件事。

两处刻意的克制：

- **不解析快照内容。** 内容按 adapter 私有格式存（Hermes 是 JSONL、LangGraph
  是 checkpointer 序列化格式），视图层解析它等于把界面绑死在一种记忆载体上——
  换一个适配器，这一页就得重写。所以只给条数、大小、摘要。
- **"从快照恢复"与"有缺口"分开算。** 恢复到一个内容相同的快照可能没缺口，
  恢复之后视野恰好接上也是可能的。合成一个布尔值就再也说不清是哪一种了。

### 审计日志 `/audit`

需求 3.2 的"调用拦截"和"重放审计"。单次运行的那份在运行详情页里，
这一页是**跨运行**的——"这个工具是不是老被拒绝"这种问题得横着看。

两个细节：

- **被出口代理拒绝的调用整行标出来，但明说它不算 Agent 的异常行为。**
  那是 ADR 003 的默认拒绝在生效，不是被测对象做错了事，混进检测结论会污染
  判定。但它们值得单独看：一次被拒的调用意味着 Agent 试图访问白名单之外的
  东西，那既是它的行为，也是这条策略真的在起作用的证据。
- **截断必须自报。** 一页最多 200 行，超了就在页面上写"还有 N 条没显示"，
  并直说不要拿这一页去下"从来没被拒绝过"这种结论。静默截断会让人基于残页
  得出一个看起来很正常的结论——这正是本项目一直在防的那类失效。

筛选下拉的选项**从实际记录里取，不从工具声明里取**：声明了但一次都没调用过的
工具出现在筛选里是白费力气。

### 回归集 `/regression`

架构篇 3.6（场景 5）要的是"把一次异常存成回归用例"。它是这套工具里唯一一个**跨时间**
的模块：其它页看的都是"这一次跑成什么样"，这一页问的是"我认定这个结论是对的之后，
它还好不好"。

**最关键的一处：这个页面给的是两个并列的答案，不是一个。**

```
这次比较算不算数？    comparable / config_changed / test_changed / unknown
差在哪？              逐条差异清单
```

把两者合成一句"发现 3 处差异"，就是把判断丢回给用户。而这两个答案的**组合**才是
真正有用的信息：

| 可比性 | 差异 | 该读成 |
|---|---|---|
| `comparable` | 有 | 配置没动，结论变了——这是真的行为差异 |
| `config_changed` | 有 | **不作数**。用户刚改过 Prompt / 换过工具，差异可能就是这么来的 |
| `test_changed` | 有 | 两次比的是**两套测试**，比出来的东西没有意义 |
| `unknown` | 有 | 至少一侧没有指纹（历史运行），没法判断 |

配置变了却报"回归"，用户会去查一个他刚刚亲手改过的东西。所以配置一变，结论直接
是 `indeterminate`（比不出来），差异清单**照样给**——但页面上写清了它不构成结论。

**`test_changed` 是单独一档，不是配置变更的一种。** 改 `script` / `expect` 这两节
意味着**测试本身**变了，比改 Prompt 严重一档：改 Prompt 是"被测对象可能变了"，
改脚本是"尺子变了"。

用例的基线是**冻结的一份拷贝**，不是指向某次运行。用例记的是"有人在某个时刻认定
这个结论是对的"，那是一个**断言**，断言必须自足。只存运行 id 的话，运行记录被清理
之后用例会静默退化成"没有基线"，而它在列表里看起来仍然完好——静默退化比报错难查
得多。运行被清理了就在列表里写明"运行已清理"，而不是显示一个空的结论。

页面打开时默认比**最近一次**运行，且排除两条：

- 基线那次运行——基线往往就是当时最近的一次（人总是在跑对的那次上点"存为用例"），
  不排除就会拿基线和它自己比，渲染出一句"配置一致，结论未变"。什么都没说，读起来
  却像"我确认过，没退化"。
- **建用例之前**跑的那些——回归问的是"断言之后它还好不好"，一条早于断言的运行回答
  不了这个问题。不排除的话，用户刚建完用例还没重跑，页面就会拿一次旧运行报"结论未
  变"。

分界用 `created_at` 而不是基线运行的 `started_at`：前者是用户**做出断言**的时刻。

`POST /regression` 从**运行记录**取数，不从表单取——从表单取的话，一条被改过的请求
就能造出一条基线，而它是后续所有比对的判据。没有结论的运行（跑崩了、在结论字段存在
之前跑的）**当不了基线**：拿"未留存"当基线，之后每次比对都会报出"未留存 → 不通过"
这样一个假差异，而它看起来像是真抓到了退化。这条规则写在 `regression/cases.py` 而不
是路由里——将来多一个调用方（命令行、导入脚本）就会绕过路由上的检查。

一键回归跑完跳回**这个用例的对比页**（`?run_id=` 指向刚跑完那次），而不是运行详情页：
点了"回归测试"的人要看的下一件事是"和基线比怎么样"。跳转目标由作业携带
（`Job.return_to` 里带 `{run_id}` 占位），但只接受以单个 `/` 开头的站内地址——
`//evil.example` 和 `https://…` 一律拒绝，退回运行详情页。

## 长时运行的世界时间

**只对长时运行显示。** 普通运行根本不出现这一块——否则读的人分不出"这次没做时间
加速"和"这次做了但没动"，前者正常，后者是故障。

面板里**两个数必须并列**：

```
模拟跨度   1.2 天（世界自己的时间）
真实耗时   17.3 秒（约 6238 倍）
```

只印"模拟跨度 1.2 天"，读的人会以为跑一次要一天，于是不会去跑它；只印"耗时 17.3 秒"，
就看不出这次到底模拟了多久。少任何一个，这块面板都在误导。秒数转人话用的是
`formatting.span_human`，与命令行报告**同一份实现**——两份实现意味着网页和命令行
可能对同一个数给出不同说法，而读的人第一个念头是"哪个坏了"。

**时钟对不上时整块变红。** 每段会话旁边写着"距上一段过了 30 小时"，如果引擎实际没
拨那么久，页面上直接列出声明值与实际值，并说明**这是加速器的自检、不是对被测对象的
判断**。加速器坏掉之后世界停在原地，检测器照样给出一份看起来正常的报告，读的人会
以为"Agent 隔了一天还是这么干"——实际上什么都没测到。

页面底下挂一句不支持声明：**Agent 进程内的定时器不受这个时钟影响**。它自己的
sleep、cron 走的仍是真实时间。写在页面上而不是只写在文档里，因为读报告的人不会去
翻文档，而他会拿这份报告去推断"Agent 隔夜会怎么做"。

## 测试

`tests/test_api.py`，84 条。用 `httpx.ASGITransport` 而不是 `TestClient`——后者会
为每个请求起一个新的事件循环，而这个应用的状态（作业登记表）活在事件循环里，
用 `TestClient` 测出来的并发行为和真实运行时不是一回事。

夹具里的报告快照**照着运行器真正写出来的形状造**（成本那一格直接问
`CostRollup.to_dict()` 要），不手写字典。这条规矩是被一次真事故换来的：夹具和代码
用着同一个错键（`total_usd`，而运行器写的是 `cost_usd`），于是那段对比在真实数据上
从来没报过任何东西，而测试一直是绿的——**两边一致地错**。夹具比真实报告瘦一圈，
就等于让一整类只有真数据才走得到的路径永远没被走过。
