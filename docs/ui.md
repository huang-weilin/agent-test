## 零 JavaScript

轮询用 `<meta http-equiv="refresh" content="2">`，保存用 form POST，删除以外没有
任何交互需要脚本。所以浏览器关掉 JS 它照样能用，也没有"前端资源没构建"这类故障模式。

代价说清楚：**运行中页面整页刷新**，输入框里没提交的编辑会丢。这在等待页上无所谓
（那里本来没有输入框），但意味着不能把编辑器和运行状态放在同一页。目前是分开的。

## 五条约束

### 1. 只绑回环地址，且不给远程开关

`serve()` 对 `127.0.0.1` / `::1` / `localhost` 之外的主机**直接抛 `ValueError`**，
不是打警告。这个服务没有任何认证，而它能写场景文件、能拉起子进程——绑 `0.0.0.0`
等于把"往这台机器上写文件"开放给整个局域网。

刻意**不留** `--host` 逃生舱：留了就等于认可那条路。要远程访问，用 SSH 端口转发；

```bash
ssh -L 8765:127.0.0.1:8765 <主机>
```

那条路上至少有认证和加密。`tests/test_api.py` 里有一条测试直接钉住
`DEFAULT_HOST == "127.0.0.1"`，另一条钉住 `serve()` 会拒绝 `0.0.0.0`。

### 2. 一次只跑一个，第二个请求返回 409

不是保守，是执行器**物理上不能并发**：它运行期间改进程级全局
`settings.tool_upstream_base_url`（`runner.py:342`），把出口代理指向本次运行自己那个
mock 的端口。两个运行重叠的话，后启动的会把前一个的地址改掉——前一个的代理于是去敲
**后一个的 mock**，两边数据互相写进对方的目标系统，而**两份报告都看起来正常**。

这正是本项目一直在防的那类失效：报告读起来没问题，结论是错的。

**不做队列。** 第二个请求直接拒绝，并明说"`clean` 正在跑，等它结束"。排队更友好，
但用户对着一个没有解释的转圈等一分钟，不如收到一句能读懂的话。

判断"有没有人在跑"没有加锁：asyncio 单线程，而检查与置位之间没有 `await`，
从事件循环视角是一步完成的原子操作（`api/jobs.py`）。

### 3. 结论标签有三种，`NULL` 不是 `False`

`TestRun.verdict_ok` 是**可空**的，界面上对应三种显示：

| `verdict_ok` | 显示 | 含义 |
|---|---|---|
| `True` | `通过` | 运行跑完，判定通过 |
| `False` | `不通过` | 运行跑完，判定不通过 |
| `NULL` | `未留存` | **没有留下结论**——加这个字段之前跑的历史运行 |

把 `NULL` 显示成红叉，等于替一条没有结论的运行编一个结论出来，用户会去查一个根本
不存在的缺陷。`report_json` 同理：`parse_report()` 对老运行返回 `None`，页面与
`/api/runs/{id}` 都明确说"未留存（在本字段存在之前跑的）。**不是失败。**"

`verdict_ok`（**判定**）与 `status`（**执行**）是两件事，不要合并：一次正常跑完的运行
完全可能不通过；而 `loop` 场景里被熔断杀掉的那次运行，`status='killed'` 却恰恰是**通过**的。

结论与运行分两次写：`finish_run()` 在执行结束那一刻发生，而结论要等检测器跑完、
预期比对完才知道（`trace/recorder.py` 的 `record_verdict`）。作业**先**记录结论、
**再**置 `state="done"`，所以跳到报告页时结论一定已经落库，不会闪出"未留存"。

**同一条规矩在报告页最上面那一块也是。** `/runs/{id}` 顶上有一句「所以呢、我该干什么」
（`api/explain.py` 的 `NEXT_STEP`）：一句人话 + 一个下一步，四种底色。它**不新增任何
判定**——判定仍然只有 `ScenarioResult.ok` 与 `ExpectResult.ok` 两处，它只是把三个已经
算好的结论读成人话；页面上那句话的语气必须和底下卡片一致，由
`tests/test_run_summary.py` 拿真 `ok` 现算核对。两处措辞是刻意写死的：

- **「通过」那句话里不许出现不加否定的「没问题」。** 原文是「这次没查出你在场景里
  点名要查的那些毛病」加上「它不等于「Agent 没问题」」——这个工具全部的价值就建立在
  「判不了」和「通过」严格分开上，而这一句是读的人**唯一一定看得见**的那句。
- **旧快照（`expectation` 里没有 `ok` 键）既不放绿也不放红**，明说「没记下比对结果」，
  和上面 `verdict_ok=NULL` 显示成「未留存」是同一条规矩。库里那几百份历史运行都是
  这种，页面上会一直这么显示——**这不是坏了，是那些快照真的没记**。

这一段是切片 1 加的，动机是第一个真实用户的原话：「能跑通但看不懂」。

### 4. 场景标识走白名单

`api/paths.py` 是**整个 Web 层唯一碰磁盘的地方**。从 URL 取来的字符串会被拼进文件
路径，不校验就是一个任意文件写。两道防线：

- 标识必须匹配 `^[a-z0-9][a-z0-9_-]{0,63}$`——挡掉分隔符与 `.`；
- 拼出来的路径再做一次**包含性检查**（`path.parent != base` 就拒绝），
  这一道不依赖正则的细节。

`tests/test_api.py` 用 13 个畸形标识参数化钉住这件事：`../`、`..\`、`a/b`、
`/etc/passwd`、`C:/windows`、空串、大写 `Clean`、`.hidden`、`clean.yaml`（扩展名会
变成 `clean.yaml.yaml`）、含空格的、65 字符的超长的、非 ASCII 的。另有一条走 HTTP
层，用 URL 编码的 `..%2F..%2Fetc%2Fpasswd` 确认路由层不越权。

列场景时**文件名不合法的也照样列出来**，并说明它为什么打不开。从列表里藏掉的话，
用户看见文件在磁盘上却怎么都找不到它。

### 5. 保存之前先校验

写进磁盘的文本必须先能被 `load_scenario` 读出来。**全部用例都在这些文件里，写坏
一个等于弄丢一个用例**——而用户不会立刻发现，他只会发现"我的场景不见了"。

校验不过时不落盘，并把**用户刚敲的内容**回显到编辑框（不是磁盘上的），否则一次
笔误就变成一次静默的改动丢失。落盘走 `tempfile.mkstemp` + `os.replace`，是原子的。

连"新建场景"的骨架也要经解析器过一遍——不然就会有一个"编辑器一保存就报错"的默认场景。

## 顺带定下的几件事

| 决定 | 为什么 |
|---|---|
| **没有 JSON 写接口** | 改场景文件只有 HTML 表单一条路，于是路径校验、先校验后落盘只在一个地方落地，不用维护两套写入口的等价性。将来真需要，把表单处理器抽出来即可 |
| **场景不存在就 404，不给空编辑器** | 空编辑器点保存就凭空建出一个场景来，于是"新建"有两条路径，其中一条用户根本不知道自己走了。新建只有一个入口：列表页那个表单 |
| **跑的是磁盘上那份，不是编辑框里的** | 未保存的改动不参与运行。不然"我改了怎么结果没变"会变成一个查不出所以然的问题。页面上也这么写 |
| **关掉 `/docs` 与 `/redoc`** | 它们没有任何认证，而这个服务能拉起进程。接口不复杂，`/api/*` 的路径本身就是文档 |
| **`reload=False`** | 热重载会在文件变动时重启进程；一次运行正在跑的时候重启，会留下一批"永远进行中"的运行记录 |
| **模板引擎（Jinja2）** | **引它的理由是自动转义，不是排版。** 检测器结论、Agent 的 stdout、工具参数全是外部输入，手写 f-string 拼 HTML 意味着每一处都要记得 `html.escape`，漏一处就是一个 XSS。有一条测试专门钉这件事 |
| **强调写 `<strong>`，不写 Markdown 的 `**`** | 页面上那些字是给人读的，而强调落在哪个词上就是意思的一部分（"**不算** Agent 的行为"）。浏览器不认识 `**`——它把星号原样打出来，于是作者以为自己加粗了，读的人看到一堆符号。有一条静态测试扫模板源文件钉住它，跳过 Jinja 注释与 `<code>`/`<pre>` |

## 几个"视图"模块，难点都不在查询

需求第 229 行的六个模块里，`记忆视图`、`审计日志`、`回归集`、调用链、跨会话差异 都是
在已有数据上面看东西，难点不在查询本身：前几个技术上很薄，真正要花心思的是**别把话
说错**——它们各自有一句话会说反；后几个有真的逻辑（差分引擎、链的合并与归因），但它
们的风险一样是**给出一个读起来像结论、其实不作数的结论**。

### 自主行为面板（运行详情页）

**只在运行里有无人值守的会话时出现。** 普通运行里挂一个空的自主行为面板，读的人
分不出"这次没做自主测试"和"这次做了但没测到东西"——和世界时间那一块同一个道理。

面板里只有两件事，但两件都不能少：

```
无人值守的会话                  #0
被授权无人值守运行的工具        （没有任何工具被授权。无人值守时它做的任何写操作都算越权。）
```

**"未经授权"这四个字，没有第二行就没法复核。** 读的人得知道当时允许了什么，才能
判断哪一条算越权；只印结论的话他只能选择信或不信，而这份报告的全部意义就是让他
不必信。

三处刻意的地方：

- **这份授权随报告一起存的，不是渲染时现查场景。** 场景文件事后会被编辑，去读
  今天的那一份，会让上周的报告显示成今天的授权——"未经授权"这四个字于是悄悄换掉
  了对象，而报告读起来完全正常。
- **会话表里标出哪一段没人看着**（`无人值守：这一段没有人在场`），但**不给它一个
  通过/不通过的徽章**：无人值守是一个**范围**，不是一个判定。染成红色会让读的人
  以为这一条本身出了问题。同一串调用，旁边写着"无人值守"和没写，读出来的行为
  完全不同——前者是它自己决定的，后者是用户让它做的。
- **"声明不拦截"写在页面上，不只写在文档里。** 读报告的人不翻文档，而他会拿这份
  报告去推断"这笔钱到底出没出去"。答案是：出去了，除非出口代理拦了它。

### 记忆观测面板（运行详情页）

**这张表说的是"哪个时点上记忆里有哪些文件、哪些动过"，不是"它记住了什么"。**
和记忆快照那块并列，但两件事完全不同：快照是**操纵**（我们回滚到哪儿），观测是
**读**（会话边界上看见的样子）。

```
时点        视野    条目  新出现              消失  内容变了
会话 1结束  ≤ 序号0   1    notes/order-A1.md   —    —
会话 2开始  ≤ 序号0   1    —                   —    —
会话 2结束  ≤ 序号0   2    scratch/log.md      —    notes/order-A1.md
```

三处刻意的：

- **"内容变了"这一栏不是判定。** Agent 往记忆里写东西是它的本职工作。这栏的用处
  是让人看到"这段会话动过哪些文件"；算不算漂移由场景声明的判据决定，结论在下面
  "检测结论"里。页面上原话写着"不是判定"——不写的话，这一栏会被直接读成问题清单。
- **表格不带内容，只有路径与摘要。** 报告长期保留，而记忆里可能有用户真实数据。
  要看内容按摘要去本地库里取快照。
- **"会话边界"这四个字写在页面上。** 读报告的人不翻文档，而他会顺手把这张表读成
  "全程都在看着"——中途改了又改回来的其实看不见。页面原文："中途改了又改回来的
  看不见"。

旧格式的报告（这一栏存在之前跑的）没有 `memory` 键，页面说"没记录不是没问题"，
**不显示"记忆正常"**——空着和印一句好话，都会把没记录读成检查通过了。

编辑器右侧那张卡还多一件事：场景**声明**了哪些记忆判据（`must_hold` 的路径、
`forbidden` 的标记，各带理由），以及那句适用范围——中毒检测只管声明过的标记。
卡片上只写"2 条必须保持"的话，读的人很自然会以为记忆被盯着了，而实际盯着的是
那两条命名的路径。

### 调用链面板（运行详情页）

**面板上的每一句话都在防同一件事：把"紧接着"读成"因为"。** 它只把一段会话里的
调用按发生顺序排出来（规则与不支持清单见 `docs/call-chain.md`）。

```
调用链
会话 #0 · 目标系统报错之后
  会话 #0：5 次工具调用，2 次没成功。
  #   调用                                    边界上记下的
  1   get_order(order_id="NOPE")           !! 没成功：目标系统回了错
  3   get_order(order_id="A1")             ·  成功
  ·   第 1 次调用 get_order（…）没成功：… 同样的调用在这段会话里一共出现了 2 次（第 1、2 次）：…
```

四处刻意的：

- **`#` 那一列印的是"这一段里的第几次调用"，不是运行序号。** 序号是工具调用和
  LLM 调用共用的，印出来是 2、4、6、9 这种跳号，读者会以为中间有几次没显示出来
  ——链上最不能出的错就是让人以为少了东西。
- **标记不复用检测结论那套 `ok` / `!!` / `?` / `..`。** 那些是判定；链上是陈述。
  同一套符号会让读者以为标了 `!!` 的调用已经被判成缺陷了，所以换成 `·` / `!!` / `--`，
  并且**我们动的手（沙箱拦下、快照重放）跟它自己的失败分开标**——混在一起就等于
  替被测对象背锅。
- **同样的失败合并成一句带次数**（"一共出现了 2 次（第 1、2 次）"）。逐次列出来的话，
  一段循环会刷满屏，而"一共几次、中间隔着什么"恰恰是要看的东西。
- **旧报告说的是"这里不写'没有出错'"**——没记录不是没问题，是没记录。和记忆观测、
  跨会话差异两节同一条规矩。一次会话都没走到的运行则整节不出现。

`test_the_call_chain_panel_does_not_blame_the_agent_for_our_own_block`、
`test_the_call_chain_panel_says_it_is_not_a_verdict` 与
`test_a_legacy_report_does_not_claim_nothing_failed` 钉的就是后两条。

### 跨会话差异面板（运行详情页）

**面板上的每一句话都在防同一件事：把"有差异"读成"它退化了"。** 这个面板只列
事实，判定留给下面的检测结论（规则与不支持清单见 `docs/session-diff.md`）。

```
会话 #0 ↔ 会话 #1
会话 #0 与 #1：3 条调用对 3 条，其中 2 条一模一样，1 条对不上
  · 两段之间世界往前走了 1.2 天（…）：目标系统的状态变了，这是场景故意设的变量。
  · 记忆视野不同：… ——两段看到的起点不一样，差异可能来自这里。
差异            工具            会话 #0      会话 #1     说明
只在对照那一段  create_payment  没有         1 次（…）   create_payment：只在会话 #1 出现…
```

四处刻意的：

- **"我们动过的东西"单独一段列出**（记忆回滚、世界时间、无人值守）。它们是
  **我们让它不一样**，不是**它的行为变了**——而这两件事在报告上长得一模一样。
  不单列的话，读的人只能选择信或不信。
- **一样的部分也要给数**（"其中 2 条一模一样"）。只列差异的报告看不出它其实是把
  该做的都做了、只多了一条，而那正是这个面板要回答的问题。
- **截断自报**："还有 6 条差异没列出来——这份报告是按每对最多 12 条截的"。上限
  读的是**这份报告存下的那个数**，不是模板里的字面量：一份半年后打开的旧报告，
  得说得出它当时被截到多少条。
- **只有一段会话的场景，整节都不出现。** 没有可对照的对象，印一句"没有差异"会
  让人以为比对过了。旧格式的报告（这一栏存在之前跑的）说的是"没记录不是没问题"
  ——和记忆观测那一节同一条规矩：「没记录」和「没问题」是两回事。

`test_a_legacy_report_does_not_claim_the_two_sessions_matched` 与
`test_a_single_session_report_gets_no_diff_panel` 钉的就是后两条。

### 记忆视图 `/memory`

需求 3.4 要的是"跨会话记忆管理"。但这一页**不能显示"Agent 记住了什么"**：
记忆在 Agent 进程内，不在 ADR 001 的网络边界上，边界拦不到它。

所以它显示的是**我们的操纵让它的视野从哪里开始**。判据是
`Session.memory_horizon_ordinal`，页面上把缺口显式算出来：

```
会话 #1 视野=-1 应有=0 缺=[0]   → Agent 不可能知道序号 0 那笔付款 → 不怪它
会话 #1 视野= 0 应有=0 缺=[]    → 它本可以知道 → 怪它
```

**这两行是整个三方受控实验的 UI 版。** 同一个重复扣款，场景、脚本、扣款
次数全都一样，唯一的差别是回滚到哪儿——于是"缺不缺序号 0"就是归因的全部依据。
说反了用户会去改一个没问题的 Prompt，这正是这一页存在的理由。
`test_attribution_flips_on_the_gap_alone` 钉的就是这件事。

两处刻意的克制：

- **不解析快照内容。** 内容按 adapter 私有格式存（Hermes 是 JSONL、LangGraph
  是 checkpointer 序列化格式），视图层解析它等于把界面绑死在一种记忆载体上——
  换一个适配器，这一页就得重写。所以只给条数、大小、摘要。
- **"从快照恢复"与"有缺口"分开算。** 恢复到一个内容相同的快照可能没缺口，
  恢复之后视野恰好接上也是可能的。合成一个布尔值就再也说不清是哪一种了。

### 审计日志 `/audit`

需求 3.2 的"调用拦截"和"重放审计"。单次运行的那份在运行详情页里，
这一页是**跨运行**的——"这个工具是不是老被拒绝"这种问题得横着看。

两个细节：

- **被出口代理拒绝的调用整行标出来，但明说它不算 Agent 的异常行为。**
  那是 ADR 003 的默认拒绝在生效，不是被测对象做错了事，混进检测结论会污染
  判定。但它们值得单独看：一次被拒的调用意味着 Agent 试图访问白名单之外的
  东西，那既是它的行为，也是这条策略真的在起作用的证据。
- **参数不合规的调用（状态 `invalid_args`）反过来算 Agent 的行为。** 它和"代理拦下"
  挨着出现，但结论相反：真实的 API 一样会回 400，所以它进检测结论（`tool_schema`），
  不被"不算异常行为"那句话豁免。两句话都写在页面上——少一句，读的人就会把这一条
  也划到"沙箱干的"里去。
- **截断必须自报。** 一页最多 200 行，超了就在页面上写"还有 N 条没显示"，
  并直说不要拿这一页去下"从来没被拒绝过"这种结论。静默截断会让人基于残页
  得出一个看起来很正常的结论——这正是本项目一直在防的那类失效。

筛选下拉的选项**从实际记录里取，不从工具声明里取**：声明了但一次都没调用过的
工具出现在筛选里是白费力气。

### 回归集 `/regression`

架构篇 3.6（场景 5）要的是"把一次异常存成回归用例"。它是这套工具里唯一一个**跨时间**
的模块：其它页看的都是"这一次跑成什么样"，这一页问的是"我认定这个结论是对的之后，
它还好不好"。

**最关键的一处：这个页面给的是两个并列的答案，不是一个。**

```
这次比较算不算数？    comparable / config_changed / test_changed / unknown
差在哪？              逐条差异清单
```

把两者合成一句"发现 3 处差异"，就是把判断丢回给用户。而这两个答案的**组合**才是
真正有用的信息：

| 可比性 | 差异 | 该读成 |
|---|---|---|
| `comparable` | 有 | 配置没动，结论变了——这是真的行为差异 |
| `config_changed` | 有 | **不作数**。用户刚改过 Prompt / 换过工具，差异可能就是这么来的 |
| `test_changed` | 有 | 两次比的是**两套测试**，比出来的东西没有意义 |
| `unknown` | 有 | 至少一侧没有指纹（历史运行），没法判断 |

配置变了却报"回归"，用户会去查一个他刚刚亲手改过的东西。所以配置一变，结论直接
是 `indeterminate`（比不出来），差异清单**照样给**——但页面上写清了它不构成结论。

**`test_changed` 是单独一档，不是配置变更的一种。** 改 `script` / `expect` 这两节
意味着**测试本身**变了，比改 Prompt 严重一档：改 Prompt 是"被测对象可能变了"，
改脚本是"尺子变了"。

用例的基线是**冻结的一份拷贝**，不是指向某次运行。用例记的是"有人在某个时刻认定
这个结论是对的"，那是一个**断言**，断言必须自足。只存运行 id 的话，运行记录被清理
之后用例会静默退化成"没有基线"，而它在列表里看起来仍然完好——静默退化比报错难查
得多。运行被清理了就在列表里写明"运行已清理"，而不是显示一个空的结论。

页面打开时默认比**最近一次**运行，且排除两条：

- 基线那次运行——基线往往就是当时最近的一次（人总是在跑对的那次上点"存为用例"），
  不排除就会拿基线和它自己比，渲染出一句"配置一致，结论未变"。什么都没说，读起来
  却像"我确认过，没退化"。
- **建用例之前**跑的那些——回归问的是"断言之后它还好不好"，一条早于断言的运行回答
  不了这个问题。不排除的话，用户刚建完用例还没重跑，页面就会拿一次旧运行报"结论未
  变"。

分界用 `created_at` 而不是基线运行的 `started_at`：前者是用户**做出断言**的时刻。

`POST /regression` 从**运行记录**取数，不从表单取——从表单取的话，一条被改过的请求
就能造出一条基线，而它是后续所有比对的判据。没有结论的运行（跑崩了、在结论字段存在
之前跑的）**当不了基线**：拿"未留存"当基线，之后每次比对都会报出"未留存 → 不通过"
这样一个假差异，而它看起来像是真抓到了退化。这条规则写在 `regression/cases.py` 而不
是路由里——将来多一个调用方（命令行、导入脚本）就会绕过路由上的检查。

一键回归跑完跳回**这个用例的对比页**（`?run_id=` 指向刚跑完那次），而不是运行详情页：
点了"回归测试"的人要看的下一件事是"和基线比怎么样"。跳转目标由作业携带
（`Job.return_to` 里带 `{run_id}` 占位），但只接受以单个 `/` 开头的站内地址——
`//evil.example` 和 `https://…` 一律拒绝，退回运行详情页。

### 一键体检 `/checkup`

这一页和上面每一页的差别只有一条：**读者是谁**。它假定读者不知道检测器叫什么、
不知道"预期比对"是什么，只想知道"我这个 Agent 有没有毛病"。所以菜单上每一项是
一个问句（「同一笔钱，它会不会付两次？」），而不是一支场景名。

它**不新增任何判定**——判卷标准仍归场景自己的 `expect`，体检只是一层读法。详见
`docs/checkup.md`。界面这一层有三处是这里才有的：

**一趟体检是一个作业、串行 N 步，不是 N 个作业。** 执行槽只有一个（见上面第 2 条
约束），而且即便能并发也不该并发：把 N 项排进队列各自入队，中间被别的运行插进来
是**看不见的**——页面上仍然是六格、每格都有结论，只是那六格已经不是同一趟的数据了。

**进度页就地变成结论页，不跳走。** 普通运行跑完跳到 `/runs/{id}`，那是它唯一的那份
记录；一趟体检有六次运行记录，跳去哪一次都是错的，因为结论是这六次**合起来**的那一份。

**结论按 `item.id` 对回菜单，不按数组下标对。** 菜单在跑的过程中被改过时（删了一项、
改了标识），对不回的步骤会单独列出来并说明菜单被改过。按下标硬对的话，A 项的结论会
安到 B 项的问题底下——那一页读起来完全正常，而它是错的。

结论页是**现算的**，不是跑完存下来的：每次运行各自的结论快照永久留在自己的运行记录
里，这一页只做"换个读法"。存一份合成结果就有两份会各自漂的东西，而漂了之后没有任何
东西会让它变红。代价是服务重启之后这一页看不到了——但每次运行自己的记录一个字不少。

### 新建测试向导 `/scenarios/new`

**这一页存在的理由只有一条：那个「通过」到底在判什么，必须由用户来说，而且他必须
看得见自己说的是什么。**

在此之前新建场景只有一条路——拿一份骨架去手写 YAML，29 个字段加一堆跨字段校验。
写得出的人不需要向导，写不出的人（这个工具真正的读者）就卡在门口。但把入口降低
不等于把标准交给机器去猜，所以两件看着像捷径的事都**没做**：

**没做「自由描述 → 机器翻译成判定」。** 那样最后那个「通过」判的是机器对用户那句话
的理解，不是用户的意思。翻错了报告会振振有词地说"通过了"，而用户没有任何办法发现
——他看到的是一句他自己写的话。

**没做流程图编辑器。** 流程图能表达"先做 A 再做 B"，但表不了"什么算对"，而"什么算对"
是这套工具唯一值钱的东西。而且它只是换一种要学的东西：不写代码的人改成学画图，
等于换了一门代码。

所以第三问是**一列勾选的毛病**，一条对应一个真实存在的检测器，配上「我预期会被抓到」
/「我预期一切正常」/「这次不用它」三选一。这一层映射（`wizard.verdict_for`）是整个
向导唯一一处能把"该报警"和"不该报警"对调的地方，所以：

**确认页印的是 `verdict` 那个词本身（`fail` / `pass`），不是旁边那句人话。** 旁边那句
是给读的人理解的，那三个字是机器真正照做的。两者并排放在保存按钮上面，极性写反的话
用户有机会当场发现——这是这一页唯一一处"必须存盘之前看见"的东西。

**警告区说的是「你勾的这个，这一趟根本触发不了」，不是"提醒一下"。** 向导能犯的最坏
的错就是生成一份加载得了、跑得起来、报告漂漂亮亮，而判卷标准**触发不了**的场景——
用户拿着它上生产，因为他自己勾过那一条。所以机械判得出来的矛盾都会当场说：
只跑一遍却预期"会被抓到重复扣款"（造不出重复）、跑两遍却预期"一切正常"（那会变成
一份每次都红的假警报）、钱那栏和脚本里的写调用次数对不上、跨会话那一条配了一段会话、
无人值守那两条配了没有无人值守的一趟、声明成"授权它这么做"又预期"它会被判越权"。

**两个方向都要判，而且判据只能是"真的矛盾"。** 只会误报的闸门，用户很快就学会无视
整个警告框，而真正该看的那几条也跟着一起被无视了。两处是量出来的：

- **钱那一栏的判据是"两个数不相等"，不是"没勾写工具"。** 原先写成后者，于是
  「只勾只读工具 + 钱最多扣 0 笔」——一份完全自洽的阴性对照——会被报成"那个数对不上"，
  而报告上它显示的是「对得上」（算的是 `egress_charges == 0`，两边都是 0）。
  提醒说对不上、报告说对得上，分歧本身比漏报更难发现。
- **"重复扣款抓不到"有两个各自独立的原因：只跑一遍，和一个写工具都没勾。**
  原先只判了前一个，于是「同一件事做两次 + 只勾只读工具 + 预期会被抓到重复扣款」
  一声不吭地过去——同样是判卷标准永远触发不了的场景。补上之后，
  `test_the_warnings_only_look_at_the_tools_you_picked` 那条测试才第一次真的盯住了
  它名字里那件事：它此前只断言了**原料**（勾中的工具里没有写工具、写调用是 0 次），
  从没断言那句提醒真的说了出来，所以那条例外飘了两个版本它都是绿的。

**自由文本框只写进 `description`，确认页上明说机器不判它。** 「这个 Agent 是干什么的」
「这次要验证什么」是写给人看的；没有这句声明的话，用户会以为模型在判它们。

**没有 session、没有第二步的隐藏状态。** 服务端什么都不存：确认页拿到的就是表单里
那些答案，重新算一遍给出 YAML。所以刷新确认页不会丢东西，也不会出现"第二步看到的和
第一步填的不一样"。「返回改一改」把原始表单原样填回去，不做任何重新解读——包括**认不
出的取值退回默认而不是兜成某一档**，以及「钱最多扣几笔」那一栏填错时把原文留着。

**保存走的是现有的 `POST /scenarios/{id}/save`**（先 `parse_scenario` 再落盘）。向导
没有第二条写盘路径，所以它产出的场景和手写的场景没有任何区别——跑的是同一个引擎，
判卷的是同一套检测器。三条附加的拒绝在这一步之前发生，都是"存下去会出事"的那种：

| 拒绝 | 不拦会怎样 |
|---|---|
| 标识叫 `new` | 路由先注册的先匹配，一份真叫 `new` 的场景从此永远打不开 |
| 标识已经存在 | 保存是**无条件覆盖**的，点两下就把那份场景换掉，磁盘上不留痕迹 |
| `id:` 和文件名不一致 | 界面按**文件名**找人，运行记录存的是文件里那个 `id`；不一致时报告点进去打开的是另一个场景，而且没有任何东西报错 |

## 长时运行的世界时间

**只对长时运行显示。** 普通运行根本不出现这一块——否则读的人分不出"这次没做时间
加速"和"这次做了但没动"，前者正常，后者是故障。

面板里**两个数必须并列**：

```
模拟跨度   1.2 天（世界自己的时间）
真实耗时   17.3 秒（约 6238 倍）
```

只印"模拟跨度 1.2 天"，读的人会以为跑一次要一天，于是不会去跑它；只印"耗时 17.3 秒"，
就看不出这次到底模拟了多久。少任何一个，这块面板都在误导。秒数转人话用的是
`formatting.span_human`，与命令行报告**同一份实现**——两份实现意味着网页和命令行
可能对同一个数给出不同说法，而读的人第一个念头是"哪个坏了"。

**时钟对不上时整块变红。** 每段会话旁边写着"距上一段过了 30 小时"，如果引擎实际没
拨那么久，页面上直接列出声明值与实际值，并说明**这是加速器的自检、不是对被测对象的
判断**。加速器坏掉之后世界停在原地，检测器照样给出一份看起来正常的报告，读的人会
以为"Agent 隔了一天还是这么干"——实际上什么都没测到。

页面底下挂一句不支持声明：**Agent 进程内的定时器不受这个时钟影响**。它自己的
sleep、cron 走的仍是真实时间。写在页面上而不是只写在文档里，因为读报告的人不会去
翻文档，而他会拿这份报告去推断"Agent 隔夜会怎么做"。

## 还没做

| 缺口 | 影响 |
|---|---|
| 删场景 | 界面上删不掉，只能去磁盘上删。写操作越少越安全，但这条迟早要补 |
| 运行中逐条刷新 | 整页刷新，看不到"跑到第几步了" |
| 记忆内容逐字对比 | 运行页那张表现在只说"哪个文件的摘要变了"，说不出**变的是哪几个字**。要看得先给 `MemoryAdapter` 加一个**只读的**导出接口，而不是让视图层去猜格式（`entries_of` 就是为这件事开的口子，但报告刻意不落内容） |
| 跨会话差异只列前若干条 | 差异超过 12 条时后面列不出来，页面会自报条数但没有"展开全部"。真出现那种场景再说：现在的场景最多几条 |
| 调用链不标"哪一步是出事的起点" | 面板给的是顺序、次数和"紧接着"，不给一个箭头指出"痛点在这次"。要说起点就得判因果，而边界上只有顺序 |

## 测试

`tests/test_api.py`，120 条。用 `httpx.ASGITransport` 而不是 `TestClient`——后者会
为每个请求起一个新的事件循环，而这个应用的状态（作业登记表）活在事件循环里，
用 `TestClient` 测出来的并发行为和真实运行时不是一回事。

夹具里的报告快照**照着运行器真正写出来的形状造**（成本那一格直接问
`CostRollup.to_dict()` 要），不手写字典。这条规矩是被一次真事故换来的：夹具和代码
用着同一个错键（`total_usd`，而运行器写的是 `cost_usd`），于是那段对比在真实数据上
从来没报过任何东西，而测试一直是绿的——**两边一致地错**。夹具比真实报告瘦一圈，
就等于让一整类只有真数据才走得到的路径永远没被走过。
