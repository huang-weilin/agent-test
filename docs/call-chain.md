# 调用链（需求 3.2 P1）

需求原文：**展示错误如何在工具调用链中传播。**

这句话里最要紧的是**传播**，而它是个因果词。所以这份文档一半在讲它做了什么，
一半在讲它**不写什么**。

```bash
.venv/Scripts/python.exe scripts/run_scenario.py scenarios/target_error.yaml
```

`scenarios/target_error.yaml` 是给这一节准备的素材：目标系统对 `get_order(NOPE)`
回 404，Agent 原样又问了一次，然后换成存在的订单问，最后正常付款。

## 一句话

> **写的是顺序，不是因果。**

边界上看得见的是**紧接着**：第 1 次调用没成功，第 2 次调用还是同一个工具、
参数一模一样。报告写得出"紧接着又是一次同样的调用"，写不出"它在重试"——后一句
是读的人下的结论。

两个说法只差一点，但一个是我们观测到的，另一个是我们替 Agent 解释的，而**解释错了
没有任何一处会报错**。整份报告里给人看的字都不含"因为""所以""因此"，这条措辞纪律
由 `tests/test_call_chain.py::test_the_chain_never_says_because` 钉住。

同一条规矩的另一半：**这是陈述，不是判定。** 它不进 `findings`、不影响 `ok`。
目标系统回了个错，是发生在这条链上的事，不等于被测对象做错了事。谁对谁错看检测
结论那一节。

## 链上有什么

一段会话一条链，节点按**发生顺序**排（按 `seq` 排，不是按喂进来的顺序）。

| 一列 | 是什么 |
|---|---|
| 第 N 次 | 在这段会话里是第几次**工具调用** |
| 工具与参数 | `get_order(order_id="NOPE")`。参数渲染与跨会话差异共用 `sandbox/formatting.py`，两处不许各写一套 |
| 标记 | `·` 成功 / `!!` 它自己没成功 / `--` 我们动的手 |
| 说明 | 没成功的那几次写清是谁的原因 |

### 编号为什么不用运行序号

`seq` 是工具调用和 LLM 调用**共用**的计数器。一次工具调用前后各有一条 LLM 调用，
所以真实序号是 2、4、6、9 这种跳号。原样印出来，读者会以为中间有几次没显示出来
——而链上最不能出的错就是让人以为少了东西。

所以报告印的是 `position`（这一段里的第几次调用，1 起），`seq` 仍然留在 JSON 里：
要和审计页、检测结论里的"序号"对上时靠它。

### 标记为什么不复用检测结论那套符号

检测结论用 `ok` / `!!` / `?` / `..`，那些是**判定**。链上是陈述，共用符号会让读者
以为链上标了 `!!` 的调用已经被判成缺陷了。所以换一套：`·` / `!!` / `--`。

## 四种"谁的错"分开标

一次调用在边界上留下的，除了工具和参数，就只有"是不是成功了"和"没成功是谁的原因"。

| 标记 | 谁的原因 | 怎么读 |
|---|---|---|
| `target_error` | 目标系统 | 回了非 2xx。**最硬的一种"出错"**——真实世界的回答 |
| `invalid_args` | 被测对象 | 参数不符合场景声明的 schema，在边界上被拒。真实 API 一样会拒，所以算它自己的问题 |
| `undeclared_tool` | 被测对象 | 调了场景里没声明的工具 |
| `sandbox_blocked` | **我们** | 被沙箱的出口策略拦下。**这不是它的失败** |
| `replayed` | **我们** | 快照恢复时的重放。也不是它主动发的 |
| `unknown` | 不知道 | 认不出来的 status。**不许猜成"目标系统报错"**——猜错方向会冤枉目标系统 |

前四种进 `failed` 计数，后两种进 `ours` 计数，**两个数分开报**。把"沙箱拦的"混进
"它失败了"里，等于替被测对象背锅——这和 `blocked_by_proxy` 是同一条规矩的两个入口：
那个标记只说明"沙箱自己的策略在生效"，标反了会同时骗过循环检测和审计页。

`replayed` 优先于 `sandbox_blocked`：两者都是我们干的，但一条重放如果被读成
"沙箱拦了它"，读者会去找一条**其实没发生过的拦截规则**。

## 紧接着的那一次

每条"没成功"的记录后面跟着一句：那之后紧接着发生的是什么。

| 关系 | 写法 |
|---|---|
| 同一个工具、同一个参数指纹 | "紧接着又是同一个调用（get_order），参数一模一样" |
| 同一个工具、参数变了 | "紧接着还是 get_order，参数变了" |
| 换了个工具 | "紧接着换成了别的工具（create_payment）" |
| 紧接着是一条重放 | "紧接着是一次快照重放（get_order），**不是它主动重发**" |
| 这一段就结束了 | "这一段的调用就结束了"；被熔断终止时补一句"（这一段被熔断终止）" |

两条各自有理由：

- **重放要特判。** 一次重放的指纹和原调用一模一样，不特判的话它看起来正好像是
  "它在原样重试"——而那是恢复机制干的（`docs/detectors.md` 第三节第 3 条）。
  **这一行今天印不出来**：没有任何生产路径会写下 `replay_reason` 这个标记，所以链上
  不会出现"紧接着是一次快照重放"。留着它是为了让那句话有一个已备好的位置，而不是
  因为现在能说出这句话。
- **"结束了"要分清是谁结束的。** 被熔断终止是我们的看门狗动的手，自己停下来可能是
  它做了个决定。同一句话，两种含义。

### 同样的失败合并成一句

按 `(工具, 参数指纹, 标记)` 合并。两处同样的失败不是两行，是一行带次数：

> 第 1 次调用 get_order（order_id="NOPE"）没成功：目标系统回了错。同样的调用在这段
> 会话里一共出现了 2 次（第 1、2 次）：第 1 次之后紧接着又是同一个调用（get_order），
> 参数一模一样；第 2 次之后紧接着还是 get_order，参数变了。

合并是**刻意的不精确**：逐次列出来的话，一段循环会刷满屏，而读者要的恰恰是"同样的
失败一共几次、中间隔着什么"。第一次之后和最后一次之后各说各的——它们可以不一样，
而那正是"这条错沿着链怎么走"。

## 干净的和空的不一样

| 这一段 | 报告写 |
|---|---|
| 有调用、全成功 | "5 次工具调用，没有一次不成功。" |
| 有调用、只有我们拦的 | "5 次工具调用，1 次是沙箱拦下或重放的。"——**不写"没有一次不成功"** |
| 一次调用都没有 | "一次工具调用都没有。" |

第二行是那个容易漏的：我们拦下的那一次不算它失败，但也**不能因此说这一段是干净的**
——"没有一次不成功"是一句关于它的话，而这一次它的调用根本没出去，说它成功、说它
失败都是在说一件没发生的事。

第三行同样要说：沉默会让"没有调用"和"没这一段"长得一样。

## 长报告不静默截断

| 上限 | 值 | 超了会怎样 |
|---|---|---|
| 一段会话列多少次调用 | 30 | 报告里写"下面只按顺序列了前 30 次，还有 N 次没列出来" |
| 一段会话列几种失败 | 8 | 命令行写"还有 N 种没成功的调用没列出来（每段会话最多列 8 种）" |

静默截断会让"就调了这几下"读成"后面什么都没发生"，而后面往往正是出事的地方。

**两个上限跟着报告一起存**（`CallChain.node_limit` / `step_limit`）：一份旧报告要能
说出**它当时**是按多少截的。用今天的常量去说，是一句关于现在的话，没法核对。

## 命令行与界面

命令行是报告里的一节：

```
--- 调用链（每段会话里，调用按发生顺序）---
  会话 #0：5 次工具调用，2 次没成功。
     !! 第 1 次 get_order（order_id="NOPE"）——没成功：目标系统回了错
     · 第 3 次 get_order（order_id="A1"）
     > 第 1 次调用 get_order（order_id="NOPE"）没成功：目标系统回了错。同样的调用在
       这段会话里一共出现了 2 次（第 1、2 次）：……
  这一节是陈述，不是判定：目标系统回了个错不等于被测对象做错了事，所以……
```

界面在 `/runs/{id}` 的「调用链」面板：每段会话一张表（`#` / 调用 / 边界上记下的），
没成功的那几行标红、我们动的那几行标黄，底下是那几句"紧接着"。

三条容易看漏的：

- **前提没成立时链照列**，但会指回「会话」那一节——那段轨迹不指向被测对象的行为。
- **旧报告（这一栏还不存在时存的）会说"这里不写'没有出错'"**：没记录不是没问题，
  是没记录。写成"没有出错"就是拿沉默当证据。
- **一次会话都没走到时不出这一节**，不是出一节空的。

## 不支持清单

| 做不到 | 为什么 |
|---|---|
| 说"它在重试""它放弃了" | 因果不在边界上。链只写"紧接着" |
| 数"几次才算异常" | 阈值要按工具、按业务语义定，那是检测器的职责（`loop` 已经有一套）。链再定一套，两个数打架时读者不知道该信谁 |
| 看到 Agent 的**理由** | 它说的话不在边界上，工具返回值按 ADR 002 根本不落库 |
| 比对工具**返回体** | 边界只留参数指纹，不留返回体（这是 `docs/detectors.md` 第九节同一条边界） |
| 一次列完超长会话 | 两个上限会自报，看全的用审计页 |
