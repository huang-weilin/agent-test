# 跨会话差异报告（需求 3.1 P1）

需求原文：**对比同一场景在不同会话中的行为差异。**

一个场景可以有好几段会话（`docs/scenarios.md` 的 `sessions`），长时运行的场景里
它们之间世界还往前走了一大截。报告要能回答：

> **它这一段做的事，和那一段做的事，一样吗？**

`scenarios/long_run_overnight.yaml`、三个 `cross_session_*.yaml` 都是现成的素材。

## 一句话

> **这是陈述，不是判定。**

它不进 `findings`，不影响这次运行通过与否。同一个场景的两段会话本来就允许不一样
——长时运行的场景里，第二段看到的世界都不一样了。把"有差异"判成失败，等于把长时
运行的正常形态报成缺陷。

要判"该不该不一样"，看的是检测结论：`idempotency` 说跨会话重复扣款有没有发生、
`memory.*` 说声明的记忆键有没有守住。差异报告只负责**把不一样的地方摆出来**。

## 怎么对齐

| 步骤 | 判据 |
|---|---|
| 分组 | 按 `session_ordinal` 拆开。**不用墙钟时间**——同一个理由写在 `docs/longrun.md`：墙钟会把同一段会话里隔了几毫秒的调用切成两段，那依赖机器快慢 |
| 配对 | 同工具 + **同参数指纹**（`sandbox.trace.normalize.fingerprint`，与幂等检测同一个判据）算"同一件事"，先配对 |
| 基准 | 取**第一段有工具调用**的会话。前面那段空的会留一句说明，不会被静默丢掉 |

对不上的部分按下面五种说，一种都不许含糊过去：

| 种类 | 什么时候 | 长什么样 |
|---|---|---|
| `only_base` | 只有基准那段发了 | 「只在会话 #0 出现（2 次（seq 1、4）），会话 #1 里没有」 |
| `only_other` | 只有对照那段发了 | 同上，方向相反 |
| `count_differs` | 指纹一样、次数不同 | 「参数一模一样，但发的次数不同」 |
| `outcome_differs` | 指纹一样、次数一样，**结果**不同 | 「被出口代理拦下的次数：会话 #0 是 1 次，会话 #1 是 0 次」 |
| `args_differ` | 两边各只剩一次的同名调用 | 「按同一次调用对齐，参数不同：amount：99 变 88」 |

### 不猜配对

**只有某一侧正好剩一次、另一侧也正好剩一次，才会说"这是同一次调用、参数不同"。**
多剩一条就只能说"只在某一段出现"。

理由很具体：基准那侧有两次付款（99、88），对照那侧一次（77）。硬把第一个和它配上，
报告上会长出一句"参数从 99 变成了 88"——而那个 88 属于另一次调用，读者**没有办法
从报告上看出这句话是猜的**。宁可说"这三次里有一次对不上"，也不能编一句读起来很
确定的话。

### `outcome_differs` 为什么单独有一个

指纹里只有**工具 + 参数**。于是"同一个调用，一边被出口代理拦下、另一边放行了"和
"同一个调用，一边报错、另一边成功"都会配上对——如果不单独比一遍，报告会写
"1 条一模一样"，而那句话**观测不支持**。

所以配对之后还要比一次 `blocked_by_proxy` 与 `status`。前者是**我们自己的策略**在
生效（ADR 003 的放行名单），后者是目标系统给的回答，两者都不在指纹里。

## "有差异"和"差异算不算数"是两件事

和 `regression/diff.py` 同一条纪律，两个字段**并行**：

| 字段 | 答的是 |
|---|---|
| `comparable` / `reasons` | 这份差异能不能指向被测对象 |
| `differences` | 差异具体是什么 |

**不可比的时候差异照样列出来**，只是加一句"这可能是没跑到"。反过来做——不可比就
不列——读的人只会看到一片空白，而空白和"没有差异"长得一模一样。

什么会让它不可比：

- 某一段的**脚本没跑完**（`premise_held` 为假且不是熔断）。它少做的那些事不一定
  是行为差异，可能只是没跑到。
- 某一段的**时钟对不上**：这一段的世界不是场景声明的那个世界，差异可能来自加速器。

熔断**不算**前提不成立（`docs/longrun.md` 里那条既有规则）：循环场景的预期结果就是
被熔断。不豁免的话，一个完美触发的循环场景会被报成"没测到"。

## 我们动过的东西单独列

这一节是这份报告最容易被忽略、又最要紧的部分。

两段会话之间**我们**动过这些：记忆被回滚到某个快照、世界被往前拨了 30 小时、这一段
无人值守。它们是**我们让它不一样**，不是**它的行为变了**——而这两件事在报告上长得
一模一样。不单独列出来的话，读的人只能选择信或不信。

```
  会话 #0 与 #1：3 条调用对 3 条，其中 2 条一模一样，1 条对不上
     · 两段之间世界往前走了 1.2 天（会话 #1 开始时世界是 2026-10-01T10:18:11+00:00）：
       目标系统的状态变了，这是场景故意设的变量。
     · 记忆视野不同：会话 #0 是什么都记不得，会话 #1 是记得会话 #0 结束时写下的东西
       ——两段看到的起点不一样，差异可能来自这里。
```

记忆视野那一行尤其重要：`docs/detectors.md` 里那条归因规则（视野早于基准 → 是我们
回滚的，不是 Agent 丢了）在这里被摆到读者面前，而不是留在代码里。

**措辞纪律：这里一律叫"差异"，不叫"回归""退化"。** 同一个场景的两段会话不一样，
可能是场景故意设的；说成"退化"就是在给一个中性事实判方向，而报告里没有任何东西
支持那个方向。

## 长报告不静默截断

每对会话最多列 12 条差异，超了**必须自报**：

```
     还有 6 条差异没列出来（每对会话最多列 12 条）。
```

同上，**"一样的部分"也要给数**：「3 条调用对 3 条，其中 2 条一模一样」。一份只列
差异的报告，看不出它其实是把该做的都做了、只多了一条——而那正是这个面板要回答的
问题。

## 命令行与界面

命令行在记忆观测之后、检测结论之前：

```bash
.venv/Scripts/python.exe scripts/run_scenario.py scenarios/long_run_overnight.yaml
```

Web 界面在运行页「会话」表之后，标题是**跨会话差异**。只有一段会话的场景**整节都不
出现**（没有可对照的对象，印一句"没有差异"会让人以为比对过了）；**旧格式的报告**
（这一栏存在之前跑的）出现的是一句"没记录不是没问题"——「没记录」和「没问题」是
两回事，和记忆观测那一节的规矩一样。

## 不支持清单

**不假装支持。** 这些不是实现遗漏，是这一节的边界：

- **看不见会话**中途**发生了什么。** 对齐的对象是会话序列上的工具调用；同一段会话里
  改了又改回来的，在这里和在记忆观测里一样看不见。
- **只比工具调用。** Agent 说的话、目标系统返回的正文都不在这里（边界只留返回体的
  字节数，正文不留）。两段会话可以"调用完全一样"而做的事完全不同——这句话写在
  面板上，不留给读者自己想到。
- **不同场景之间不比。** 那件事归 `regression/diff.py`（同一条用例的两次运行）。
- **不判轻重。** 五条差异排在一起，报告不说哪条更要紧。要排序就得知道业务语义，
  而那是场景声明的事，不是报告的事。
