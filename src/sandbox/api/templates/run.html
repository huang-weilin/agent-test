被出口代理拒绝的调用（blocked_by_proxy）不计入 Agent 异常行为—— 那是沙箱自己的策略（ADR 003 出口默认拒绝）在生效，不是被测对象做错了事。 混进检测结论会污染判定。

状态为 invalid_args 的调用是另一回事：它的参数不符合场景里 声明的 schema，在到达目标系统之前就被拒绝了。这算 Agent 的行为 ——真实的 API 一样会回 400，所以它进了检测结论（tool_schema）。 拦在这里还守住了地面真值：一笔用非法参数扣出来的钱，在报告上和一笔正常的 扣款长得一模一样。

「耗时」和「其中看门狗」是两笔时间，不是一笔的两个算法。 耗时 是出口代理到目标系统的往返，在看门狗扫之前 就量完了；其中看门狗 是我们自己在那次调用上花掉的时间——看门狗 是在这个请求里 await 的，而 Agent 正阻塞在这个请求上等它， 所以这笔时间记在被测会话的墙钟上。分开列是因为它们会一起 把一次运行拖到单会话超时，而混在一起之后，一次"因为我们太慢而超时"的运行 和一次"Agent 自己慢"的运行，报告上长得一模一样。看门狗的代价随调用次数 超线性地涨（见 docs/detectors.md）。

「其中看门狗」里的 — 是没跑过，不是 0：被边界 拦下的调用（未声明的工具、走错入口、出口被拒、参数不合 schema）在目标系统上 什么都没留下，看门狗不为它们扫；这一列加出来之前落的行也在这里。把没跑读成 0，等于替一次没发生过的测量报一个数。
