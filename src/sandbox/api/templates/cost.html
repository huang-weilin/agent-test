归期用运行的开始时间，不是每次调用的时间戳。 一次运行整个算在它开始的那个周期里。按调用时间归期的话，跑过零点的运行 会被劈成两半，两边的数都对不上任何一次运行——而对不上账的账单比没有账单更糟。

没做的：按工具拆解

需求要求按 Agent、工具、场景三个维度拆解。Agent 和场景做了，工具没做， 因为做不出一个诚实的版本：工具调用本身不花 token，token 花在 LLM 上。 沿时间线把"产生这次工具调用的那次 LLM 调用"配上去是个错的近似—— 工具返回的内容会留在上下文里，让之后每一次调用继续为它付钱。 硬报一个数，用户会拿它去砍工具，而那个数是错的。
